# 채팅·메시지 관리 확장 — 장기 개발 지침서

> 기준일: 2026-11-01 | 문서 상태: 초안 v1 (계속 갱신) | GitHub: ggang55158891-dev/ST-Message-Navigator
>
> **이 문서는 향후 대화와 개발 작업의 기준점이다.** 구현 전에 먼저 최신 코드 및 이 문서를 함께 읽는다. 이 문서에 기록된 '계획'은 구현을 뜻하지 않으며, 실제 구현 상태는 항상 GitHub main의 소스와 테스트를 통해 재검증한다.

## 0. 목적과 범위

**최상위 목표:** SillyTavern에서 채팅과 메시지를 쉽고 빠르게 **찾고, 이동하고, 분류하고, 보존하고, 관리하는** 범용 확장을 만든다.

- 채팅·메시지 **이동 및 관리 기능**이 디자인, 애니메이션, 이름보다 항상 우선한다.
- 사용자는 추후 기능을 계속 추가하거나 우선순위를 바꿀 수 있다. 이 문서는 **고정된 최종 사양이 아닌 살아 있는 작업 지침서**다.
- 현재의 '엘리베이터: 채팅=건물, 메시지=층' 메타포는 **선택 가능한 시각 콘셉트**이지 데이터 모델의 일부가 아니다. 추후 다른 콘셉트로 전면 교체할 수 있어야 한다.
- SillyTavern이 가진 원래 메시지/채팅/스와이프 데이터와 사용자가 붙인 **별명·폴더·태그·북마크 같은 관리 데이터**를 구분한다.
- 사용자의 원본 채팅 파일(.jsonl), 캐릭터, 그룹 채팅 및 기존 확장 데이터를 보호한다.
- 다른 확장들과의 공존, 대형 채팅의 성능, 모바일 및 다양한 SillyTavern 환경을 장기 배포 목표에 포함한다.

### 변화가 있어도 지킬 원칙

1. **비파괴 우선:** 단순 탐색·별명·폴더·즐겨찾기·디자인을 위해 원문 메시지나 채팅 파일을 불필요하게 수정하지 않는다.
2. **기능과 표현 분리:** 메시지 이동 엔진, 채팅 관리 저장소, 검색 인덱스, UI 및 테마 프리셋을 서로 독립시킨다.
3. **공식 기능 우선:** SillyTavern의 지원되는 API/이벤트/채팅 전환 기능을 우선하고 내부 함수 의존성은 한 곳에 격리한다. 버전 차이는 기능 탐지로 처리한다.
4. **식별자와 표시 이름 분리:** 채팅 별명이나 사용자 지정 메시지 제목을 파일 식별자로 쓰지 않는다. 보이는 번호(#0부터)와 실제 안정 식별자는 다른 개념이다.
5. **확인 가능한 안정성:** 테스트 없이 '완료', '무충돌', '범용 호환'이라 주장하지 않는다. 실사용 브라우저 검증과 단위 테스트를 구분해 기록한다.
6. **데이터 이전 가능:** 데이터 구조를 바꿀 때는 버전, 마이그레이션, 백업, 복구 방법을 먼저 정한다.
7. **점진적 개발:** 한 PR/한 릴리스에 서로 의존하지 않는 거대한 기능을 묶지 않는다. 문제 발생 시 손쉽게 되돌릴 수 있어야 한다.

## 1. 현재 기준선 (GitHub main, 확인일 2026-11-01)

**manifest.json 버전: 1.3.0.** 아래 항목은 저장소 소스에서 확인한 구현 요소이며, 실제 SillyTavern 설치 환경에서의 모든 조합이 검증됐다는 뜻은 아니다.

### 이미 존재하는 기능

- 메시지 처음/이전/다음/마지막 이동, 버튼 드래그·위치 저장, 이동 버튼 전체/개요만 표시 설정.
- 현재 채팅의 메시지 개요(번호 #0부터, 자동 추출 제목, 사용자 지정 제목 편집, 캐릭터 표시, 검색, 10개 단위 그룹 접기/펼치기).
- 숨김 메시지(is_system) 이동 필터, 과거 메시지 추가 로딩, 현재 메시지 판정 및 위치 강조.
- 사용자 지정 제목: 메시지 식별 필드 **stmn_message_id_v1**와 채팅 메타데이터 **stmn_message_outline_v1** 활용. 브랜치 복사, 메시지 복제, 외부 확장과의 상호작용은 별도 검증 대상.
- 엘리베이터 UI: 현재 건물(채팅)·층(메시지) 표시, 층 안내/건물 로비 탭, **현재 캐릭터 또는 현재 그룹 안에서** 채팅 목록·검색·정렬·전환.
- 테마 프리셋 Classic / Restricted Floor / Sky Lift와 Sky Lift 자동/낮/밤.
- Node.js 단위 테스트, GitHub Actions의 JS 문법 및 단위 테스트 검사.

### 아직 구현됐다고 보면 안 되는 핵심 사항

- 모든 캐릭터를 아우르는 전역 채팅 라이브러리, 별명/가상 폴더/태그/즐겨찾기/커스텀 표지.
- 다른 채팅의 메시지 제목·본문 전체 검색 인덱스, 마지막 메시지 확장 미리보기.
- 스와이프 개별 별표·태그·비교, 대량 선택·삭제·복원.
- 안전한 통합 진단 로그, 자동 브라우저 E2E 테스트, Cut & Paste 호환성 검증.
- 전체 사용자 환경에서의 안정성·충돌 없음·모바일 최적화의 확인.

## 2. 장기 개발 로드맵: 선행 관계에 따른 순서

> 각 단계의 상태는 기본적으로 **미착수**다. 상세 기능에 별도 표시가 없더라도 완료로 간주하지 않는다. 단계 이름의 A~H는 출시 버전 번호가 아니다.

### A. 안정성·진단·테스트 기반 [가장 먼저]

**의존성:** 기존 v1.3.0 코드의 기능 동작 확인.

**A-01 오류 진단 시스템**
- 모듈별 카테고리: lifecycle, navigation, scrolling, chat-switch, save, search, swipe, compatibility, UI.
- 기록 항목: 발생 시각, 확장·SillyTavern 버전, 현재 캐릭터/그룹 범위, 요청한 채팅·메시지 ID(기본은 익명화), 실제 결과, 오류 코드, 이벤트 순서, 경과 시간.
- **원문 대사·민감한 내용·사용자 경로·개인정보는 기본 로그에 기록하지 않는다.** 공유용 로그 내보내기 전 미리보기·민감 정보 제거.
- 제한된 크기의 메모리 순환 버퍼, 로그 켜기/끄기, 다운로드/복사, 오류 발생 시 간단한 상태 알림. 로그 자체가 렌더링/채팅을 방해하면 안 된다.
- 합격: 이동 또는 채팅 전환 실패 시 언제·무엇이 실패했는지 재현 가능한 정보를 얻을 수 있음.

**A-02 테스트 기반**
- Node 단위 테스트 유지 + 브라우저 DOM 통합 테스트 도입(가능하면 Playwright 등).
- 실제 이벤트와 DOM 변경, 스크롤 제한, 숨김 메시지, 긴 메시지, 동적 이미지 로딩, 모바일 너비, 키보드/터치, 채팅 전환, 브랜치 복제/스와이프 등 재현.
- **최적화 확장과의 충돌 사례**를 회귀 테스트 항목으로 보존. 비활성/활성 비교 실험 설계.
- 모든 기능 변경 PR에서 해당 기능의 회귀 테스트 보강.

**A-03 백업/설정 검사 기반**
- 기존 확장 설정과 채팅 메타데이터 스키마 검증, 이전 데이터의 손상·중복 식별자 처리.
- 확장 전용 관리 데이터의 내보내기/복원 시나리오 설계, 버전 필드와 복구 방법 문서화.
- 오류 시 다른 확장이나 SillyTavern을 망가뜨리지 않는 안전한 실패 및 사용자 알림.

**단계 완료 조건:** 진단 로그가 정상 작동하고, 단위/브라우저 회귀 테스트의 최소 환경이 마련되며, 기존 데이터 보존 경로가 확인됨.

### B. 기존 메시지 탐색 편의 개선 [A 이후, 비파괴]

**B-01 개요 진입 시 최근 메시지 위치**
- 패널을 열면 마지막 메시지의 제목이 보이도록 목록을 초기 배치.
- 마지막 메시지가 접힌 10개 구간 안에 있으면 해당 그룹을 펼침.
- 사용자가 같은 패널을 잠시 닫았다 다시 열었을 때 스크롤 위치를 기억할지 정책 결정(기본은 마지막 메시지 우선으로 검토).

**B-02 개요 목록 전용 맨 위/맨 아래 버튼**
- 패널 아래의 남는 공간 또는 하단 툴바에 목록 이동 버튼 배치.
- **목록 자체의 스크롤**과 실제 채팅 메시지로 이동하는 동작을 명확히 구분.
- 접힌 그룹/검색 상태에서의 상하단 의미 정의.

**B-03 마지막 메시지 버튼 2단계**
- 첫 번째 클릭은 마지막 메시지 **시작 지점**으로 이동.
- 마지막 메시지 시작 지점을 이미 선택한 상태에서 두 번째 클릭하면 채팅 **스크롤 맨 아래**로 이동.
- 중간에 다른 메시지 이동·수동 스크롤·채팅 교체·렌더링 변경이 있으면 2단계 상태를 적절히 초기화.
- UI 자동 스크롤/이미지 로딩/타 확장의 스크롤 변경에서도 엉뚱한 메시지로 이동하지 않도록 테스트.

**B-04 패널 크기 조절**
- 사용자가 패널 너비/높이를 드래그로 바꾸고 설정으로 저장.
- 뷰포트 밖으로 나가지 않게 제한하고, 작은 화면에선 적절히 접거나 재배치.
- 버튼 위치 드래그와 패널 크기 드래그의 포인터 충돌 방지.

**단계 완료 조건:** 사용자가 가장 최신 메시지를 열고, 찾고, 아래로 내려가는 모든 경로가 안정적으로 동작. 기존 #0 번호 및 메시지 제목 편집 보존.

### C. 관리 데이터 토대 [D~G의 필수 기반]

**C-01 안정적 채팅 참조 모델**
- 채팅을 **(소속 캐릭터/그룹 범위 + 원본 채팅 파일 식별자)** 조합으로 우선 참조.
- 장기적으로 별도 내부 logical ID의 도입 가능성 검토. 기존 채팅에 무조건 새 필드를 삽입하거나 모든 파일을 즉시 다시 저장하지 않는다.
- 파일명 변경, 동일 이름의 다른 캐릭터 채팅, 그룹 채팅, 채팅 복제/브랜치, 캐릭터 이름/아바타 변경, Cut & Paste 메시지 복사 등에서 충돌·유실 정책 정의.
- 사용자가 보는 **별명**은 파일 경로나 ID가 아니므로 언제든 변경할 수 있어야 함.

**C-02 관리 데이터 저장소/스키마**
- 별명, folderId, favorite, tags, imageRef, lastRead, customSortOrder, createdAtSource, 관련 메시지 제목 등을 **명확한 네임스페이스와 schemaVersion** 아래 관리.
- 저장 위치 결정: extensionSettings/확장 전용 파일/채팅 메타데이터 각각의 장단점(전역 접근, 이동성, 백업, 성능, 파일 변경 위험)을 검토 후 ADR로 문서화.
- 변경은 최소 범위로 저장하며, 가능한 한 원문 채팅·메시지는 수정하지 않음. 저장 실패 시 재시도/충돌 처리/되돌리기 정책 필요.
- 기존 사용자 지정 메시지 제목 키(stmn_message_outline_v1 / stmn_message_id_v1)와의 호환 보장.

**C-03 마이그레이션·백업**
- 이전 데이터와 새 스키마를 동시에 읽을 수 있는 호환 기간, 자동 마이그레이션 전 백업, 성공·실패 메시지.
- JSON 등 이식 가능한 포맷의 설정 내보내기/가져오기(버전 확인, 중복 ID 충돌 안내, 잘못된 데이터 거부).
- 채팅 삭제·파일 이동·캐릭터 삭제 후 고아 관리 데이터를 식별하고 복구/정리하는 정책.

**단계 완료 조건:** 서로 다른 캐릭터의 동명 파일이 섞이지 않고, 별명/폴더 정보가 재시작·복제·백업 복원에서 안정적으로 보존됨.

### D. 채팅 라이브러리 — 구조화된 분류와 정렬 [C 이후]

**권장 세부 작업 순서:** 별명 → 즐겨찾기 → 가상 폴더 → 태그 → 정렬 → 커스텀 이미지.

**D-01 채팅 별명**
- SillyTavern JSONL 실제 파일명은 유지. 확장 목록에서 별명 우선, 원본 이름 확인 가능.
- 현재 캐릭터/그룹 범위를 넘어 전역 목록까지 확장하는 시점·방법 별도 결정.

**D-02 즐겨찾기·태그**
- 채팅 단위 별표 토글, 복수 태그 생성/수정/삭제, 태그 기반 필터.
- 태그 이름 변경 시 연결이 끊기지 않도록 표시명/식별자 분리.

**D-03 가상 채팅 폴더**
- 파일 시스템의 실제 채팅 파일을 옮기지 않음.
- **전체 채팅 보기 / 폴더별 보기** 제공, 폴더 생성·이름 변경·삭제·채팅 이동 지원.
- 기본 정책 후보: 채팅당 소속 폴더 하나 + 여러 태그. 하위 폴더 여부는 성능/UX 검토 후 결정.
- 폴더 삭제 시 채팅 원본은 삭제하지 않고 '미분류'로 이동.

**D-04 정렬**
- 최근 메시지 활동순(마지막 실제 메시지 시각), 생성일순(가능한 확실한 생성 기록), 폴더별 모음 + 폴더 내 최근 활동순.
- 생성일 정보가 확실하지 않으면 **추정 또는 날짜 미상** 명시. 파일 수정일을 무조건 생성일/마지막 대화일로 사용하지 않음.
- 추후 선택 기능: 사용자 지정 수동 정렬, 고정 채팅.

**D-05 채팅 전용 커스텀 이미지**
- 확장 패널에서만 보이는 채팅 표지/썸네일.
- 이미지 저장 위치, 크기·형식·참조 유효성·백업/이식 경로를 결정한 뒤 구현.
- 설정 JSON에 대용량 base64를 무제한 삽입하지 않음. 없는 이미지나 깨진 경로의 폴백 필요.

**단계 완료 조건:** 채팅 별명/폴더/즐겨찾기/태그/이미지를 변경해도 원본 파일이 불필요하게 수정되지 않으며, 정렬·폴더 보기·백업 후 복구가 일관됨.

### E. 미리보기와 채팅 전역 검색 [C/D 이후; 비용 높은 기능]

**E-01 마지막 메시지 미리보기**
- 채팅 목록의 작은 버튼으로 마지막 메시지 내용을 축약 표시. 사용자가 클릭할 때만 상세 로딩.
- 원문 길이 제한, 스포일러/비공개 이미지/HTML 처리와 캐시 무효화.

**E-02 다른 채팅의 메시지 제목 목록**
- 채팅 목록의 '창문' 버튼 클릭 시 그 채팅의 사용자 지정/자동 제목 목차를 작게 펼쳐 표시.
- 미리보기 때문에 **현재 채팅을 강제로 전환하면 안 됨**. 비활성 채팅 데이터 조회 API나 안전한 읽기 경로 필요.
- 특정 메시지를 클릭하면 해당 채팅으로 이동한 후 정확한 메시지 위치까지 2단계 탐색. 로딩 취소·채팅 변경 레이스 처리.

**E-03 검색 통합**
- 검색 가능 대상: 실제 파일명, 채팅 별명, 폴더 이름, 태그, 사용자 지정 메시지 제목, 메시지 원문.
- 검색 범위를 사용자 선택 필터로 제공(하나 또는 복수 선택).
- 제목·파일명 등 **가벼운 메타데이터 검색**과 **본문 전체 검색 인덱스**를 계층화.
- 패널을 열 때 전체 채팅을 무조건 읽지 않는다. 검색 인덱스는 지연 구축·증분 갱신·취소·캐시 크기 제한.
- 메시지가 복사/수정/삭제/스와이프/브랜치되면 관련 검색 인덱스가 갱신되거나 무효화되어야 함.
- 결과에서 원본 채팅과 메시지 번호를 정확히 표시하고 클릭해 이동 가능.

**단계 완료 조건:** 100~1000개 채팅과 대형 메시지 기록에서도 탐색 패널을 과도하게 지연시키지 않고, 조회·취소·업데이트가 안전하게 작동.

### F. 스와이프 관리 [C와 A의 안정성 기반 이후]

**F-01 개별 스와이프 즐겨찾기/태그**
- 메시지의 답변별 별표, 여러 태그, 필터링, 즐겨찾기 답변만 빠르게 비교/이동.
- SillyTavern의 swipes, swipe_id, swipe_info 데이터 구조와 스와이프 변경 이벤트/저장 API 실측 검증.
- 단순 배열 인덱스만 영구 ID로 쓰지 않음: 스와이프 삭제·재정렬·재생성·편집 시 연결을 어떻게 복구할지 설계.
- 태그 및 즐겨찾기는 원본 답변 텍스트를 변경하지 않고 기록하는 방향.

**F-02 안전한 비교 UI**
- 후보 답변을 목록·나란히·차이 강조 등으로 비교하는 방안 검토.
- 선택한 스와이프 활성화가 다른 기능의 스크롤/렌더링을 깨지 않도록 테스트.
- 삭제된 스와이프의 즐겨찾기 데이터는 고아 데이터 처리 정책 적용.

**단계 완료 조건:** 새 스와이프 생성/선택/편집/삭제/브랜치/복사 후에도 엉뚱한 답변에 별표나 태그가 붙지 않음.

### G. 다중 선택과 파일 삭제 [가장 나중]

**G-01 비파괴 일괄 관리부터**
- 채팅 여러 개 선택 → 가상 폴더 이동, 태그 부여, 즐겨찾기, 내보내기.
- 선택 대상의 캐릭터·그룹 범위 표시, 필터 전환 뒤 선택 유지/해제 정책.

**G-02 실제 파일 삭제**
- SillyTavern의 공식 삭제 기능 또는 확인된 서버 API를 사용. 파일 시스템 직접 조작 최소화.
- 삭제 전 채팅 파일별로 확인 목록, 원본 백업/내보내기 옵션, 연결된 브랜치·체크포인트·폴더·검색 인덱스 영향 안내.
- 삭제 오류·부분 실패 처리, 중복 클릭 방지, 가능하면 복원 지원.
- 기본적으로 돌이킬 수 없는 동작은 **명시적 확인 후에만** 실행.

**단계 완료 조건:** 위험한 동작의 영향과 백업 방법을 사용자에게 보여주고, 실패해도 다른 채팅이나 설정이 손상되지 않음.

### H. 배포·범용성 확보 [모든 단계에 걸쳐 실행 + 안정화 릴리스]

- SillyTavern release 및 가능하면 staging, PC/모바일, 브라우저·테마·캐릭터/그룹, 네트워크 오류 등의 매트릭스 테스트.
- 다른 확장, 특히 **최적화 확장** 및 **Cut & Paste(메시지 이동/복사)**의 충돌 재현.
- Cut & Paste로 메시지를 **복사**할 때 사용자 제목의 ID와 제목 데이터, **이동**할 때 원본/대상 채팅의 연결 관계가 어떻게 되는지 확인. 다른 확장 이름을 무작정 예외 처리하지 말고 실제 코드·이벤트를 분석.
- 성능 기준: 1개/100개/1000개+ 채팅, 100/1만+ 메시지, 인덱싱 도중 취소, DOM 가상화.
- 접근성: 키보드 포커스/ARIA/텍스트 대비/작은 화면/터치/모션 감소 설정.
- 설치/업데이트, 릴리스 노트, 기존 버전 복구, 권한·저장위치·지원 범위 문서화.
- 개인 데이터 자동 외부 업로드나 원격 분석을 기본값으로 두지 않음.

## 3. 독립 디자인 트랙 — 언제든 변경 가능

**표현을 바꾸더라도 NAV / DATA / LIBRARY / SEARCH / SWIPE의 동작은 바뀌지 않아야 한다.**

| 아이디어 | 구현 방침 | 우선순위 |
|---|---|---|
| 스카이 리프트에서만 반투명 이동 버튼 | 테마 전용 CSS 변수/규칙, 색 대비 확인 | 낮음 |
| 모던 화이트/블랙 심플 프리셋 | CSS 토큰 기반으로 추가, 기본 SillyTavern 스타일 침범 금지 | 낮음 |
| 스카이 리프트 밤하늘의 작은·촘촘한 별 | 저비용 CSS 이미지/고정 장식, 시인성·배터리 테스트 | 낮음 |
| 기본 작은 점 → 호버 시 5개 이동 버튼 확장 | 클릭·터치·드래그와의 충돌 테스트; 항상 펼침 설정 제공 | 중간 |
| '계란' 버튼(껍데기·흰자·노른자 분리) | 독립적인 스킨 애니메이션, 실제 동작을 감추지 않기 | 실험적 |
| '천사 날개' 버튼(호버 시 날개 4개) | 독립적인 스킨 애니메이션, reduced-motion 지원 | 실험적 |
| 패널 스킨/레이아웃 전면 교체 | 공통 구조·데이터 계약은 동일하게 유지 | 선택 가능 |

- 테마 프리셋 이름과 앱 이름은 확정된 제품 요구사항이 아니다.
- UI는 HTML/CSS/JS로 구현 가능하지만, 애니메이션은 과도한 이미지/파티클 작업 없이 성능 최적화.
- hover가 없는 모바일에서도 핵심 이동 버튼을 항상 사용할 수 있어야 함.

## 4. 아키텍처와 데이터 설계의 공통 계약

권장 의존성 방향:

1. **SillyTavern Adapter:** 공식 API, 버전별 기능 탐지, 이벤트 구독, 파일 정보 읽기/전환/저장.
2. **Domain & Identity:** 채팅·메시지·스와이프 식별, 메타데이터 의미, 정렬·필터 순수 함수.
3. **Repository:** 사용자 관리 데이터의 읽기/쓰기/백업/마이그레이션, 인덱스 캐시.
4. **Services:** 이동, 검색, 미리보기, 스와이프 비교, 파일 일괄 작업의 유스케이스.
5. **UI:** 탭/패널/목록/도구/로딩/알림, 이벤트를 서비스에 전달.
6. **Themes:** UI 공통 CSS 토큰 위의 프리셋. 내부 ID나 실제 파일명 참조 금지.

새 파일/모듈은 필요한 시점에만 분리한다. '미래를 대비한다'는 이유만으로 실제로 사용하지 않는 추상화와 프레임워크를 대량 도입하지 않는다.

### 식별자 관련 사고 예방

- **채팅**: 같은 파일 이름이 다른 캐릭터나 그룹에 있을 수 있다. 항상 범위를 포함해 확인한다.
- **메시지**: 화면 번호(#0, #1...)는 순서가 바뀌면 달라질 수 있다. 기존 사용자 지정 제목 ID를 맹목적으로 복사하지 않으며 중복·삭제·브랜치 검증이 필요하다.
- **스와이프**: 배열 순서는 안정된 정체성이 아니다. 변경/삭제에 대비한 매핑과 충돌 감지가 필요하다.
- **폴더·태그**: 사용자가 보는 이름은 변경 가능해야 하므로 내부 ID를 별도 관리한다.
- **생성일/활동일**: 원시 데이터의 출처와 확실성(실측/추정/미상)을 함께 저장·표시한다.

### 저장과 안전

- 데이터는 schemaVersion을 갖고, 손상된 값은 검증 실패 처리. 잘못된 저장소 상태에서 조용히 덮어쓰지 않는다.
- 가능하면 덮어쓰기 전에 변경 미리보기/백업을 제공하고, 중복 저장·채팅 전환 중 레이스를 막는다.
- 외부 확장이 같은 메시지/DOM을 갱신하더라도, 확장의 데이터 키와 CSS 선택자가 다른 확장 영역을 덮지 않게 한다.
- 화면이 보이지 않거나 데이터가 누락되었을 때 정상 채팅 자체를 차단하지 말고 확장 기능만 안전하게 실패하도록 한다.

## 5. 회귀 테스트 매트릭스와 완료 기준

| 개요 | 10개 접기/펼치기, #번호 정확 검색, 자동 제목, 사용자 제목, 빈 메시지 |
| 채팅 전환 | 현재/다른 채팅, 캐릭터/그룹, 동명 파일, 연속 클릭, 로딩 중 채팅 변경 |
| 브랜치·복사 | 브랜치 복제, 메시지 삭제·복사·이동, 고유 ID 충돌/제목 유실 |
| 관리 데이터 | 별명·폴더·태그·표지 저장/복원, 중복·고아 데이터, 설정 리셋 |

| 플랫폼 | 데스크톱/모바일, 좁은 패널, 키보드/터치/스크린리더, reduced-motion |

| 파일 파괴 작업 | 백업/미리보기/확인/오류 롤백, 선택 범위와 삭제 대상 검증 |

**한 PR의 Definition of Done (DoD):**
1. 사용자 요청·기대 동작·비범위를 명확히 기술.
2. 관련 기존 코드와 본 문서·현재 브랜치를 읽고 의존성 확인.

## 7. 보류 중 결정 사항 (정책을 임의 확정하지 말 것)

- 채팅 관리 대상: 현재 캐릭터/그룹만 우선할지, 모든 캐릭터를 포함한 전역 라이브러리를 언제 지원할지.
- 폴더: 채팅당 한 폴더 + 다중 태그를 기본값으로 할지, 복수 폴더 소속·중첩을 지원할지.
- 채팅 고유 ID: 읽기 전용 외부 매핑 vs 채팅별 메타데이터 삽입, rename/clone/Cut & Paste 동작 정책.
- 생성일 정보: 신뢰 가능한 원본 필드와 추정값의 처리/정렬.
- 커스텀 표지: 저장 위치, 이동/백업/복원 경로, 최대 용량.
- 검색 인덱스: 파일/로컬 저장소/메모리 사용 범위, 갱신 규칙, 개인정보 처리.
- 스와이프 ID: 개별 답변 변경/복사/삭제에 대한 안정 식별 정책.
- 개요 열기 동작: 항상 최신으로 시작 vs 직전 탐색 위치 유지.
- 마지막 메시지 버튼의 2단계 상태가 설정 변경/테마 변경 시 어떻게 동작할지.
- 데스크톱/모바일의 기본 UI 규칙과 확장 배포 대상 SillyTavern 버전 범위.
- **디자인 및 제품 이름은 미확정:** 현재 엘리베이터는 가변 프리셋 중 하나가 될 수도 있다.
