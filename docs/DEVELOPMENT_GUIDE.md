# 채팅·메시지 관리 확장 — 장기 개발 지침서

> 기준일: 2026-11-03 | 문서 상태: 갱신 v2 (계속 갱신) | GitHub: ggang55158891-dev/ST-Message-Navigator
>
> **이 문서는 향후 대화와 개발 작업의 기준점이다.** 구현 전에 먼저 최신 코드 및 이 문서를 함께 읽는다. 이 문서에 기록된 '계획'은 구현을 뜻하지 않으며, 실제 구현 상태는 항상 GitHub main의 소스와 테스트를 통해 재검증한다.

## 0. 목적과 범위

**최상위 목표:** SillyTavern에서 채팅과 메시지를 쉽고 빠르게 **찾고, 이동하고, 분류하고, 보존하고, 관리하는** 범용 확장을 만든다.

- 채팅·메시지 **이동 및 관리 기능**이 디자인, 애니메이션, 이름보다 항상 우선한다.
- **초보자도 예측 가능한 메뉴 구조, 최소 노출, 점진적 공개**를 UI의 기본 원칙으로 삼는다. 디자인 변경은 기능 개발 도중에도 작은 PR로 반복하고, 기능·저장소 계층과 분리한다.
- 사용자는 추후 기능을 계속 추가하거나 우선순위를 바꿀 수 있다. 이 문서는 **고정된 최종 사양이 아닌 살아 있는 작업 지침서**다.
- 현재의 '엘리베이터: 채팅=건물, 메시지=층' 메타포는 **선택 가능한 시각 콘셉트**이지 데이터 모델의 일부가 아니다. 추후 다른 콘셉트로 전면 교체할 수 있어야 한다.
- SillyTavern이 가진 원래 메시지/채팅/스와이프 데이터와 사용자가 붙인 **별명·폴더·태그·북마크 같은 관리 데이터**를 구분한다.
- 사용자의 원본 채팅 파일(.jsonl), 캐릭터, 그룹 채팅 및 기존 확장 데이터를 보호한다.
- 다른 확장들과의 공존, 대형 채팅의 성능, 모바일 및 다양한 SillyTavern 환경을 장기 배포 목표에 포함한다.

### 변화가 있어도 지킬 원칙

1. **비파괴 우선:** 단순 탐색·별명·폴더·즐겨찾기·디자인을 위해 원문 메시지나 채팅 파일을 불필요하게 수정하지 않는다.
2. **기능과 표현 분리:** 메시지 이동 엔진, 채팅 관리 저장소, 검색 인덱스, UI 및 테마 프리셋을 서로 독립시킨다.
3. **공식 기능 우선:** SillyTavern의 지원되는 API/이벤트/채팅 전환 기능을 우선하고 내부 함수 의존성은 한 곳에 격리한다. 버전 차이는 기능 탐지로 처리한다.
4. **식별자와 표시 이름 분리:** 채팅 별명이나 사용자 지정 메시지 제목을 파일 식별자로 쓰지 않는다. 보이는 번호(#0부터)와 실제 안정 식별자는 다른 개념이다.
5. **확인 가능한 안정성:** 테스트 없이 '완료', '무충돌', '범용 호환'이라 주장하지 않는다. 실사용 브라우저 검증과 단위 테스트를 구분해 기록한다.
6. **데이터 이전 가능:** 데이터 구조를 바꿀 때는 버전, 마이그레이션, 백업, 복구 방법을 먼저 정한다.
7. **점진적 개발:** 한 PR/한 릴리스에 서로 의존하지 않는 거대한 기능을 묶지 않는다. 문제 발생 시 손쉽게 되돌릴 수 있어야 한다.

## 1. 현재 기준선과 상태 구분 (2026-11-03)

**GitHub `main`의 `manifest.json`: v1.6.0 (D-01~D-04까지 병합).** 문서 안의 과거 v1.3.x/1.4.x/1.5.x 설명은 개발 이력이며 현행 기능 목록을 대신하지 않는다.

**세 가지 상태를 반드시 구분한다.**
- **[실제 구현]** GitHub `main` 소스에 반영된 기능. 단위·모의 SillyTavern Chrome 테스트 통과와 모든 실사용 환경에서의 호환성 검증은 서로 다른 문제다.
- **[HTML 실험]** 대화에서 별도로 만든 `Quiet_Elevator_v5_툴팁_목차_설명수정.html` 등 독립 프로토타입 기능. 실험용 데이터에 동작하더라도 실제 SillyTavern 확장에 구현됐다는 뜻이 아니다.
- **[계획·검증 필요]** 요구가 정해졌으나 실제 확장 미구현, 기술적 타당성·호환성·데이터 정책 추가 검토 대상.

### [실제 구현] v1.6.0 기준

- **메시지 탐색:** 처음/이전/다음/마지막 이동, 현재 위치 감지, 숨김 메시지 처리, 과거 메시지 로딩, #0 기반 메시지 목차, 자동/사용자 지정 제목, 메시지 제목 검색, 10개 묶음 접기·펼치기, 가상 목록 렌더링.
- **B단계 편의 개선:** 목차를 열면 최신 제목 위치부터, 목차 목록 자체의 맨 위/맨 아래 버튼, **마지막 메시지 버튼의 2단계 이동(마지막 메시지 시작 → 채팅 최하단)**, 패널 크기 조절·저장.
- **채팅 로비:** 현재 캐릭터 또는 그룹 범위의 채팅 목록·전환, 별명·즐겨찾기·가상 폴더·태그 CRUD, 전체/폴더별/즐겨찾기 보기, 최근 활동/생성일/폴더별/이름순 정렬, 파일명·별명·폴더명·태그명 검색.
- **저장·백업:** 전용 관리 데이터 `stmn_library_v1`, 설정 JSON 백업·검증·동의 후 복원, 관리 데이터 JSON의 비파괴 병합 복원 및 읽기 전용 상태 점검. 원본 채팅 JSONL을 임의 수정하지 않는 정책.
- **UI·성능:** Classic / Restricted Floor / Sky Lift, 이동 버튼 위치와 표시 설정, 목록 가상화와 캐시, 초기 채팅 카드 100개 렌더링·태그 편집기 지연 생성, 진단 로깅, Node 단위 테스트 및 **모의 ST Chrome** 브라우저 회귀 테스트.

### [HTML 실험] UI 시안에서 구체화한 요구사항 (실제 코드와 혼동 금지)

- **Quiet Elevator:** 극단적인 흰색·회색 중심 미니멀 UI, 넉넉한 여백, 정보보다 **이동·목록을 먼저 표시**, 나머지 기능은 목적별 메뉴에 숨김.
- **표시 우선순위 변경:** 채팅 파일명을 큰 제목으로, 사용자가 작성한 **채팅 설명**을 옆에 작은 보조문구로 표시. 현재 main의 `alias`는 별명으로 구현되어 있으므로, 설명으로 전환할 때 데이터 의미·백업·이전 정책을 확정해야 함.
- **채팅·메시지 미리보기:** 행 전체가 아니라 **눈 아이콘**에 마우스·키보드 포커스가 왔을 때에만 툴팁 표시; 눈 아이콘 **아래**에 표시. 채팅은 최근 제목 5개와 마지막 본문, 메시지는 해당 본문을 축약(본문 최대 **680자**). 눈 아이콘 클릭 시 자세한 패널; 채팅의 목차 탭에서는 최근 5개 제한 없이 **전체 메시지 제목** 표시.
- **폴더 탐색:** 전체 채팅·즐겨찾기·각 폴더·미분류를 펼쳐 그 안의 채팅 이름을 탐색하는 드롭다운 트리. 미리보기·편집과 파일 파괴 작업 분리.
- **빠른 수정:** 메시지 **제목 수정**과 채팅 **설명 수정**의 연필 버튼을 각 항목의 즐겨찾기 별 옆에 배치.
- **이동 규칙 추가 실험:** 현재 메시지 중간에서 '이전' 누름 → **현재 메시지 맨 위** → 다시 누름 → 이전 메시지. 마지막 메시지에서 '다음'도 **마지막 메시지 시작 → 다음 클릭 시 최하단**이라는 2단계 규칙. 독립 HTML에서 시뮬레이션했으며 실제 ST 채팅 DOM에 연결해야 함.
- 스와이프 전체 답변 미리보기·즐겨찾기·선택 반영은 **미구현 계획**. 장차 메시지 **원래 상단 도구 모음**에 진입 버튼을 제공하며, 개요 패널에 불필요한 버튼을 추가하지 않는다.

### [계획·검증 필요] 주요 미완료

- 다른 채팅의 마지막 메시지와 전체 목차 실제 안전 조회, 다른 캐릭터까지 전역 검색, 메시지 본문 검색 인덱스.
- 파일명 변경/복제/삭제, 다중 선택에 의한 실제 파일 작업, 커스텀 채팅 표지, 스와이프 데이터 영속화·비교·활성 스와이프 변경.
- 이전/다음 버튼의 새 2단계 규칙, Quiet Elevator UI의 실확장 이식, 별명 → 채팅 설명의 데이터 이전, 파일명 변경 후 관리 정보 재연결.
- 실제 SillyTavern 서버·다른 확장(특히 Cut & Paste) 동시 실행 및 재시작 후 데이터 영속성, 다양한 PC/모바일 브라우저·테마 조합의 통합 검증.

## 2. 장기 개발 로드맵: 선행 관계에 따른 순서

> 단계별 기능은 **[실제 구현] / [HTML 실험] / [계획·검증 필요]** 상태로 구분한다. 기존 A~D 일부는 이미 main에 병합되었지만 단계 완료 조건 전체 충족을 의미하지 않는다. A~H는 릴리스 버전 번호가 아니다.

### A. 안정성·진단·테스트 기반 [가장 먼저]

**의존성:** 기존 v1.3.0 코드의 기능 동작 확인.

**A-01 오류 진단 시스템** *([실제 구현] v1.3.1부터 순환 버퍼·토글·진단 기록 UI·JSON 내보내기와 오류 이벤트 기록; 실제 ST/타 확장 전체 조합 검증은 계속 필요.)*
- 모듈별 카테고리: lifecycle, navigation, scrolling, chat-switch, save, search, swipe, compatibility, UI.
- 기록 항목: 발생 시각, 확장·SillyTavern 버전, 현재 캐릭터/그룹 범위, 요청한 채팅·메시지 ID(기본은 익명화), 실제 결과, 오류 코드, 이벤트 순서, 경과 시간.
- **원문 대사·민감한 내용·사용자 경로·개인정보는 기본 로그에 기록하지 않는다.** 공유용 로그 내보내기 전 미리보기·민감 정보 제거.
- 제한된 크기의 메모리 순환 버퍼, 로그 켜기/끄기, 다운로드/복사, 오류 발생 시 간단한 상태 알림. 로그 자체가 렌더링/채팅을 방해하면 안 된다.
- 합격: 이동 또는 채팅 전환 실패 시 언제·무엇이 실패했는지 재현 가능한 정보를 얻을 수 있음.

**A-02 테스트 기반** *(v1.3.2: 실제 Chrome에서 모의 ST 컨텍스트로 UI·DOM 회귀 테스트 추가, 전체 SillyTavern 서버/E2E 검증은 별도 과제로 유지.)*
- Node 단위 테스트 유지 + 브라우저 DOM 통합 테스트 도입(가능하면 Playwright 등).
- 실제 이벤트와 DOM 변경, 스크롤 제한, 숨김 메시지, 긴 메시지, 동적 이미지 로딩, 모바일 너비, 키보드/터치, 채팅 전환, 브랜치 복제/스와이프 등 재현.
- **최적화 확장과의 충돌 사례**를 회귀 테스트 항목으로 보존. 비활성/활성 비교 실험 설계.
- 모든 기능 변경 PR에서 해당 기능의 회귀 테스트 보강.

**A-03 백업/설정 검사 기반** *(v1.3.3: 설정 값 정규화, 지원되는 설정 7개 백업/검증/차이 미리보기/사용자 동의 후 복원 및 사용자 제목 데이터 읽기 전용 검사 구현. 채팅 제목 데이터 자체의 백업·복구 및 새 라이브러리 데이터 스키마는 추후 C단계와 연계.)*
- 기존 확장 설정과 채팅 메타데이터 스키마 검증, 이전 데이터의 손상·중복 식별자 처리.
- 확장 전용 관리 데이터의 내보내기/복원 시나리오 설계, 버전 필드와 복구 방법 문서화.
- 오류 시 다른 확장이나 SillyTavern을 망가뜨리지 않는 안전한 실패 및 사용자 알림.

**단계 완료 조건:** 진단 로그가 정상 작동하고, 단위/브라우저 회귀 테스트의 최소 환경이 마련되며, 기존 데이터 보존 경로가 확인됨.

### B. 기존 메시지 탐색 편의 개선 [A 이후, 비파괴]

**진행 상황 ([실제 구현] v1.4.0에서 B-01~B-04 병합, v1.6.0 main에 유지):** 단위/모의 ST Chrome 검사 및 사용자 실사용 확인 이력 있음. 실제 모든 테마·타 확장 조합은 별도 검증 대상.

**B-01 개요 진입 시 최근 메시지 위치**
- 패널을 열면 마지막 메시지의 제목이 보이도록 목록을 초기 배치.
- 마지막 메시지가 접힌 10개 구간 안에 있으면 해당 그룹을 펼침.
- 사용자가 같은 패널을 잠시 닫았다 다시 열었을 때 스크롤 위치를 기억할지 정책 결정(기본은 마지막 메시지 우선으로 검토).

**B-02 개요 목록 전용 맨 위/맨 아래 버튼**
- 패널 아래의 남는 공간 또는 하단 툴바에 목록 이동 버튼 배치.
- **목록 자체의 스크롤**과 실제 채팅 메시지로 이동하는 동작을 명확히 구분.
- 접힌 그룹/검색 상태에서의 상하단 의미 정의.

**B-03 마지막 메시지 버튼 2단계**
- 첫 번째 클릭은 마지막 메시지 **시작 지점**으로 이동.
- 마지막 메시지 시작 지점을 이미 선택한 상태에서 두 번째 클릭하면 채팅 **스크롤 맨 아래**로 이동.
- 중간에 다른 메시지 이동·수동 스크롤·채팅 교체·렌더링 변경이 있으면 2단계 상태를 적절히 초기화.
- UI 자동 스크롤/이미지 로딩/타 확장의 스크롤 변경에서도 엉뚱한 메시지로 이동하지 않도록 테스트.

**B-04 패널 크기 조절**
- 사용자가 패널 너비/높이를 드래그로 바꾸고 설정으로 저장.
- 뷰포트 밖으로 나가지 않게 제한하고, 작은 화면에선 적절히 접거나 재배치.
- 버튼 위치 드래그와 패널 크기 드래그의 포인터 충돌 방지.

**B-05 이전 메시지의 2단계 이동 ([HTML 실험], main 미적용)**
- 현재 화면이 **현재 메시지 중간**일 때 '이전' 버튼 첫 클릭은 **현재 메시지 맨 위**로 돌아가기.
- 맨 위에 도착한 상태에서 다시 누를 때만 **실제 이전 메시지 시작**으로 이동. 처음부터 맨 위라면 이전 메시지로 바로 이동.
- 첫 메시지, 숨김 메시지, 과거 메시지 로딩, 수동 스크롤·동적 콘텐츠 높이 변경 시 상태 초기화와 허용 오차를 테스트.

**B-06 마지막 메시지에서 '다음'의 2단계 이동 ([HTML 실험], main 미적용)**
- 마지막 메시지의 **시작점에 도착한 경우** 다음 버튼을 한 번 더 누르면 **채팅 최하단**으로 이동. '마지막' 버튼의 B-03 규칙과 의미를 통일.
- 도중 스크롤/다른 메시지 선택·채팅 전환/답변 생성 및 동적 높이 변경 시 재판정. '이미 중간/최하단에 있음'의 경계조건은 실제 ST DOM 기준으로 확정.
- **독립 HTML에서의 스크롤 시뮬레이션은 실제 SillyTavern 본문 이동 검증이 아님.**

**단계 완료 조건:** B-01~04 보존 + B-05/06 구현 후 실제 채팅 본문에서 시작/중간/끝 상태 테스트. 기존 #0 번호 및 메시지 제목 편집 보존.

### C. 관리 데이터 토대 [D~G의 필수 기반]

**진행 상황 ([실제 구현] v1.5.0에서 C-01~C-03 병합):** 캐릭터/그룹 범위 + 채팅 파일 ID의 복합 참조, 분리된 `stmn_library_v1` 저장소/엄격한 스키마, 관리 데이터 백업·비파괴 병합 복원·검증 UI. v1.6.0에서 D단계 편집 UI와 연동. 결정 기록: [ADR-001](ADR-001-LIBRARY-STORAGE.md).

**의도적인 한계:** 파일명·아바타 변경 후 자동 ID 재연결, 대용량 서버 저장소 이전, 여러 디바이스 충돌 해결, 실제 ST 재시작 후 저장 확인 및 Cut & Paste 호환성은 아직 검증/구현하지 않았다. C 기반은 이후 기능을 위한 데이터 계층이지 D 기능의 완성을 뜻하지 않는다.


**C-01 안정적 채팅 참조 모델**
- 채팅을 **(소속 캐릭터/그룹 범위 + 원본 채팅 파일 식별자)** 조합으로 우선 참조.
- 장기적으로 별도 내부 logical ID의 도입 가능성 검토. 기존 채팅에 무조건 새 필드를 삽입하거나 모든 파일을 즉시 다시 저장하지 않는다.
- 파일명 변경, 동일 이름의 다른 캐릭터 채팅, 그룹 채팅, 채팅 복제/브랜치, 캐릭터 이름/아바타 변경, Cut & Paste 메시지 복사 등에서 충돌·유실 정책 정의.
- 사용자가 보는 **별명**은 파일 경로나 ID가 아니므로 언제든 변경할 수 있어야 함.

**C-02 관리 데이터 저장소/스키마**
- 별명, folderId, favorite, tags, imageRef, lastRead, customSortOrder, createdAtSource, 관련 메시지 제목 등을 **명확한 네임스페이스와 schemaVersion** 아래 관리.
- 저장 위치 결정: extensionSettings/확장 전용 파일/채팅 메타데이터 각각의 장단점(전역 접근, 이동성, 백업, 성능, 파일 변경 위험)을 검토 후 ADR로 문서화.
- 변경은 최소 범위로 저장하며, 가능한 한 원문 채팅·메시지는 수정하지 않음. 저장 실패 시 재시도/충돌 처리/되돌리기 정책 필요.
- 기존 사용자 지정 메시지 제목 키(stmn_message_outline_v1 / stmn_message_id_v1)와의 호환 보장.

**C-03 마이그레이션·백업**
- 이전 데이터와 새 스키마를 동시에 읽을 수 있는 호환 기간, 자동 마이그레이션 전 백업, 성공·실패 메시지.
- JSON 등 이식 가능한 포맷의 설정 내보내기/가져오기(버전 확인, 중복 ID 충돌 안내, 잘못된 데이터 거부).
- 채팅 삭제·파일 이동·캐릭터 삭제 후 고아 관리 데이터를 식별하고 복구/정리하는 정책.

**단계 완료 조건:** 서로 다른 캐릭터의 동명 파일이 섞이지 않고, 별명/폴더 정보가 재시작·복제·백업 복원에서 안정적으로 보존됨.

### D. 채팅 라이브러리 — 구조화된 분류와 정렬 [C 이후]

**진행 상태 ([실제 구현] v1.6.0 main에 D-01~D-04 병합):** 별명/원본 파일명 분리, 즐겨찾기·태그, 가상 폴더/전체·폴더별·즐겨찾기 보기, 최근 활동·생성일 미상·폴더별·이름순 정렬. 사용자 명시 조작 시 저장하고 태그 편집 DOM은 열 때만 생성. **새 Quiet Elevator '채팅 설명'은 별명 기능의 향후 대체안이지 main에 반영된 동작이 아님.**

**미완료:** D-05 커스텀 이미지(저장·이식 정책 선행), 캐릭터 전체 횡단 전역 채팅 관리, 실제 채팅 원문 및 사용자 제목 전문 검색(E단계), 원본 파일 삭제(G단계), 고아 메타데이터 재연결. 생성일이 확인되지 않은 채팅은 임의의 날짜를 만들어 표시하지 않음.


**기존 구현 순서:** 별명 → 즐겨찾기 → 가상 폴더 → 태그 → 정렬. **새 UI 변경 순서:** 데이터 이전 결정 → 채팅 설명·빠른 연필 → 폴더 펼침 탐색 → 커스텀 이미지(용량 정책 결정 후).

**D-01 채팅 별명 ([실제 구현]) → 채팅 설명 ([HTML 실험] 방향 전환)**
- v1.6.0: SillyTavern JSONL 파일명 유지, 확장 목록에서 별명 우선, 원본 이름 확인 가능.
- 새 UI 목표: **원본 파일명을 주요 이름**으로 유지하고 사용자 입력 **채팅 설명**을 옆에 작게 표시. 즐겨찾기 옆 연필 아이콘으로 설명을 곧바로 수정.
- 기존 `alias` 필드를 설명으로 재사용할지 별도 `description` 필드로 이관할지는 **미결정**. 기존 데이터/백업의 의미가 바뀌므로 무단 전환하지 않고 데이터 이전·호환 계획 수립.
- 현재 캐릭터/그룹 범위를 넘어 전역 목록까지 확장하는 시점·방법 별도 결정.

**D-02 즐겨찾기·태그**
- 채팅 단위 별표 토글, 복수 태그 생성/수정/삭제, 태그 기반 필터.
- 태그 이름 변경 시 연결이 끊기지 않도록 표시명/식별자 분리.

**D-03 가상 채팅 폴더**
- 파일 시스템의 실제 채팅 파일을 옮기지 않음.
- **전체 채팅 보기 / 폴더별 보기** 제공, 폴더 생성·이름 변경·삭제·채팅 이동 지원.
- [HTML v5 실험] 폴더 패널을 열면 **전체 채팅·즐겨찾기·각 폴더·미분류**를 **개별 드롭다운**으로 펼쳐 내부 채팅 제목을 바로 확인·선택. 일반 목록과 실제 채팅 파일 이동은 구분.
- 기본 정책 후보: 채팅당 소속 폴더 하나 + 여러 태그. 하위 폴더 여부는 성능/UX 검토 후 결정.
- 폴더 삭제 시 채팅 원본은 삭제하지 않고 '미분류'로 이동.

**D-04 정렬**
- 최근 메시지 활동순(마지막 실제 메시지 시각), 생성일순(가능한 확실한 생성 기록), 폴더별 모음 + 폴더 내 최근 활동순.
- 생성일 정보가 확실하지 않으면 **추정 또는 날짜 미상** 명시. 파일 수정일을 무조건 생성일/마지막 대화일로 사용하지 않음.
- 추후 선택 기능: 사용자 지정 수동 정렬, 고정 채팅.

**D-05 채팅 전용 커스텀 이미지**
- 확장 패널에서만 보이는 채팅 표지/썸네일.
- 이미지 저장 위치, 크기·형식·참조 유효성·백업/이식 경로를 결정한 뒤 구현.
- 설정 JSON에 대용량 base64를 무제한 삽입하지 않음. 없는 이미지나 깨진 경로의 폴백 필요.

**단계 완료 조건:** 채팅 별명/폴더/즐겨찾기/태그/이미지를 변경해도 원본 파일이 불필요하게 수정되지 않으며, 정렬·폴더 보기·백업 후 복구가 일관됨.

### E. 미리보기와 채팅 전역 검색 [C/D 이후; 비용 높은 기능]

**E-01 마지막 메시지 미리보기 ([HTML v5 실험])**
- 채팅 목록에서 **눈 아이콘** 위에 커서를 올리거나 키보드로 포커스할 때만 툴팁을 보여준다. 목록 행 전체의 hover에는 반응하지 않는다.
- 채팅 툴팁은 눈 아이콘 **아래**에 앵커링해 **'메시지 목록' → 최신 메시지 제목 5개(한 줄씩) → 구분선 → '마지막 메시지' → 최대 680자 본문** 순서로 표시. 좁은 화면에서는 뷰포트 내로 보정한다.
- 메시지 항목 툴팁도 **눈 아이콘 전용**, 아이콘 아래에 '**마지막 메시지**' 또는 해당 메시지 설명 헤더와 최대 680자 본문 표시. 긴 본문에는 스크롤 또는 생략 표시. HTML의 텍스트는 escape하여 렌더링.
- 눈 아이콘 **클릭**은 툴팁과 별개의 **상세 미리보기**를 연다. hover가 없는 기기에서는 클릭·키보드 접근 경로가 필수.
- 원문 길이 제한, 스포일러/비공개 이미지/HTML 처리와 캐시 무효화.

**E-02 다른 채팅의 메시지 제목 목록 ([HTML v5 실험])**
- 채팅 목록의 **눈 아이콘을 클릭**하면 상세 미리보기에서 **최근 메시지 / 메시지 목차** 탭으로 조회. 툴팁은 최근 5개지만 상세 **목차는 해당 채팅의 모든 메시지**를 스크롤·가상화하여 표시한다. 제목 없는 메시지/사용자 지정 제목도 처리.
- 미리보기 때문에 **현재 채팅을 강제로 전환하면 안 됨**. 비활성 채팅 데이터 조회 API나 안전한 읽기 경로 필요.
- 특정 메시지를 클릭하면 해당 채팅으로 이동한 후 정확한 메시지 위치까지 2단계 탐색. 로딩 취소·채팅 변경 레이스 처리.

**E-03 검색 통합**
- 검색 가능 대상: 실제 파일명, 채팅 별명(**설명으로 전환 시 설명도**), 폴더 이름, 태그, 사용자 지정 메시지 제목, 메시지 원문.
- 검색 범위를 사용자 선택 필터로 제공(하나 또는 복수 선택).
- 제목·파일명 등 **가벼운 메타데이터 검색**과 **본문 전체 검색 인덱스**를 계층화.
- 패널을 열 때 전체 채팅을 무조건 읽지 않는다. 검색 인덱스는 지연 구축·증분 갱신·취소·캐시 크기 제한.
- 메시지가 복사/수정/삭제/스와이프/브랜치되면 관련 검색 인덱스가 갱신되거나 무효화되어야 함.
- 결과에서 원본 채팅과 메시지 번호를 정확히 표시하고 클릭해 이동 가능.

**단계 완료 조건:** 100~1000개 채팅과 대형 메시지 기록에서도 탐색 패널을 과도하게 지연시키지 않고, 조회·취소·업데이트가 안전하게 작동.

### F. 스와이프 관리 [C와 A의 안정성 기반 이후]

**F-01 개별 스와이프 즐겨찾기/태그**
- 메시지의 답변별 별표, 여러 태그, 필터링, 즐겨찾기 답변만 빠르게 비교/이동.
- SillyTavern의 swipes, swipe_id, swipe_info 데이터 구조와 스와이프 변경 이벤트/저장 API 실측 검증.
- 단순 배열 인덱스만 영구 ID로 쓰지 않음: 스와이프 삭제·재정렬·재생성·편집 시 연결을 어떻게 복구할지 설계.
- 태그 및 즐겨찾기는 원본 답변 텍스트를 변경하지 않고 기록하는 방향.

**F-02 안전한 비교 UI**
- [계획] 이전 메시지에 속한 **모든 스와이프 본문**을 미리보기하고, 즐겨찾기/태그된 답변만 빠르게 비교하고, 선택한 스와이프를 실제 현재 채팅의 활성 답변으로 반영.
- **진입 위치:** 층 안내 목록의 추가 버튼이 아니라 **SillyTavern 메시지 상단 도구 모음(편집·삭제 등의 아이콘 영역)**. 구현 전 해당 툴바의 확장 API·DOM 변경 및 다른 확장 충돌 확인.
- 후보 답변을 목록·나란히·차이 강조 등으로 비교하는 방안 검토.
- 선택한 스와이프 활성화가 다른 기능의 스크롤/렌더링을 깨지 않도록 테스트.
- 삭제된 스와이프의 즐겨찾기 데이터는 고아 데이터 처리 정책 적용.

**단계 완료 조건:** 새 스와이프 생성/선택/편집/삭제/브랜치/복사 후에도 엉뚱한 답변에 별표나 태그가 붙지 않음.

## 3. UI 정보 구조 — Quiet Elevator 실험 지침 (2026-11-03)

> **중요:** 아래는 **[HTML 실험/확정 후보]** UI 설계. `main`의 v1.6.0 디자인/기능이 이미 바뀌었다는 의미가 아니다. **시안 파일은 대화에 별도로 제공된 `Quiet_Elevator_v5_툴팁_목차_설명수정.html`**로, GitHub 릴리스/확장 패키지에 포함되지 않았다.

### 3-1. 최우선 디자인 철학

- **극단적으로 단순한 기본 화면:** 화이트·소프트 그레이·약한 경계선·적당한 둥근 모서리·넉넉한 여백. 큰 정보 카드, 중복 툴바, 늘 펼쳐진 관리 영역을 기본값에서 제거한다.
- **목록과 이동 우선:** 기본 화면에는 앱 이름/현재 맥락, **층 안내 ↔ 건물 로비** 전환, 목록과 최소 조작만 보인다. 검색창·폴더·상세 관리·다중 선택 도구는 요청할 때만 펼친다.
- **점진적 공개:** 자주 쓰는 버튼은 가까이에 두되 기능의 나머지는 일관된 메뉴 진입점에 숨긴다. **처음 쓰는 사람도 기능 위치를 예측할 수 있어야 한다.**
- **표현과 로직 분리:** 프리셋/배치 변경으로 NAV·DATA·LIBRARY·SEARCH·SWIPE 동작을 바꾸지 않는다. CSS 토큰과 독립 UI 컴포넌트로 이식.
- **중간중간 구조 개선:** 기능 개발 완료를 기다리지 않고 사용 중 발견한 버튼 위치·정보구조 문제를 **UI 전용 소규모 PR**로 수정한다. 색/장식·테마 애니메이션은 기능 안정화 이후 다듬어도 된다.

### 3-2. 기능 카테고리와 주 출입구

내부 정보 구조는 **10개 카테고리**로 관리하지만 이를 기본 화면에 10개 탭으로 늘어놓지 않는다.

| 기능 카테고리 | 짧은 메뉴명 | 기본 진입 위치 |
|---|---|---|
| 메시지·채팅 위치 이동 | 이동 | 플로팅 이동 버튼, 항목 이름 클릭 |
| 이름·본문·번호 검색 | 검색 | 상단 돋보기 → 검색 필드·범위 체크박스 |
| 최근 본문·목차 확인 | 미리보기 | 항목별 **눈 아이콘** |
| 즐겨찾기·폴더·태그 | 분류 | 별 아이콘, 폴더 탐색, 항목별 `···` |
| 제목·설명·표지 변경 | 정보 편집 | 별 옆 **연필**(빠른 편집), 항목별 `···` |
| 개별 답변 비교·선택 | 스와이프 | 향후 메시지 **원래 상단 도구 모음** |
| 실제 파일명·복제·내보내기·삭제 | 파일 관리 | 채팅별 `···`의 별도 하위 화면 |
| 여러 채팅 동시 처리 | 다중 선택 | **목록 메뉴** → 선택 모드 → 임시 하단 작업바 |
| 레이아웃·테마·조작 | 화면 설정 | 상단 전역 `···` |
| 설정·관리 데이터 보존, 오류 점검 | 백업·진단 | 상단 전역 `···` → 고급 설정 |

### 3-3. 메뉴는 **3종류**만

1. **전체 메뉴** = 화면 최상단 `···`. **화면·조작 설정 / 백업·복원 / 진단·데이터 점검 / 도움말**. 현재 채팅 파일이나 메시지의 작업을 섞지 않는다.
2. **목록 메뉴** = 현재 목록 제목 근처의 조정 아이콘. **정렬 / 필터 / 10개 묶음 접기·펼치기 / 다중 선택**. 채팅별 파괴 작업은 넣지 않는다.
3. **항목별 메뉴** = 채팅·메시지 행 오른쪽 `···`. **채팅:** 정보 편집(설명·표지), 분류(폴더·태그·즐겨찾기), 파일 관리(파일명·내보내기·삭제). **메시지:** 제목 수정, 북마크·분류, 추후 기타 작업. 스와이프의 주 진입 버튼은 이 메뉴가 아니라 메시지 상단 도구 모음.

**버튼 의미 일관성:** 행/제목 클릭 = 이동, **눈** = 미리보기, **별** = 즐겨찾기, **연필** = 제목/설명 즉시 편집, **···** = 해당 대상 관리. 메뉴 깊이는 가급적 **2단계 이하**. 하위 메뉴가 복잡하면 다시 중첩하지 말고 상세 패널로 전환한다.

### 3-4. 화면별 기본 레이아웃

**층 안내(메시지 목록)**

- 번호 `#n`, 메시지 제목과 작성자, 최소한의 빠른 액션만 표시; 현재 메시지만 은은하게 강조.
- 즐겨찾기 옆 **제목 수정 연필**, 눈 아이콘, 항목별 `···`. 툴팁은 **눈 위 hover/focus만**, 행 hover에서는 안 띄움.
- 목록 맨 위·맨 아래는 **목차 패널 자체 이동**. 실제 채팅 이동과 혼동되지 않게 구분.
- 메시지 10개 단위 접기/펼치기·작성자/숨김/즐겨찾기 필터는 목록 메뉴에 수납.
- 기존 메시지 첫/이전/다음/마지막 이동 버튼은 사용성이 중요하므로 작은 **접이식 플로팅 도구**로 유지. 호버 의존 금지, 클릭/터치로도 열고 항상 펼침 선택 가능.

**건물 로비(채팅 목록)**

- 각 행은 **원본 채팅 파일명을 큰 글씨**, 사용자 **채팅 설명을 옆의 작은 글씨**로 표시(목표 UI). 설명 연필은 즐겨찾기 별 바로 옆; 눈은 미리보기, `···`는 관리.
- **폴더** 텍스트/아이콘 버튼으로 접이식 좌측 폴더 패널 표시. 패널 안에서 **전체 채팅·즐겨찾기·각 폴더·미분류**를 각각 독립적으로 펼쳐 소속 채팅을 바로 확인·이동.
- 기본 목록은 과도한 버튼 없이 제목·짧은 설명·최소 액션만. 검색/정렬/태그는 열 때만 표시. 현재 범위(캐릭터/그룹) 외 채팅은 탐색 정책 확정 전까지 자동 혼합하지 않음.
- 즐겨찾기 토글은 즉시 작업; 실제 파일 삭제/이름 변경은 별도의 **파일 관리**로 분리. **'가상 폴더 이동'은 실제 JSONL 파일을 옮기지 않는다**고 명확히 표기.

**미리보기와 툴팁**

- **목록 행 전체가 아니라 '눈' 아이콘 전용**. 눈 아래로 나타나고 화면 가장자리에선 위치 보정, 200~300ms 가벼운 지연·화면 이탈 시 닫힘.
- **채팅 툴팁:** '메시지 목록' / 최근 제목 **5줄** / 구분선 / '마지막 메시지' / 본문 최대 **680자**. **메시지 툴팁:** 해당 메시지 본문 최대 **680자**, 제목 헤더. 내용 없는 메시지의 안내 제공.
- **클릭한 상세 미리보기:** 다른 채팅으로 강제 전환하지 않고 **최근 메시지 / 전체 메시지 목차** 탭. 목차는 전체 항목을 보여주되 대형 채팅은 가상 스크롤로, 로딩 취소·캐시 무효화를 지원.
- 툴팁에 HTML 원문을 삽입하지 않으며 이스케이프/안전한 텍스트 렌더링. **키보드 포커스/터치로 눈 기능 접근 가능**, 시각적 hover 동작은 터치에서 대체 경로 제공.

### 3-5. 동작 유형에 맞는 조작 방식

| 동작 | 권장 위젯 |
|---|---|
| 탐색/즐겨찾기/제목·설명 빠른 편집 | 별·눈·연필 등 의미가 분명한 소형 버튼 + 접근성 이름 |
| 검색 | 돋보기 클릭 시 펼쳐지는 입력, 검색 범위 복수 체크 |
| 폴더 탐색 | 버튼 → 접이식 사이드바 → 폴더별 드롭다운 트리 |
| 정렬/필터 | 목록 메뉴 → 드롭다운/체크박스(활성 상태 표시) |
| 관리(편집·분류·파일) | `···` → **텍스트를 읽는 세로 메뉴**, 작업에 따라 상세 화면 |
| 다중 선택 | 일시적인 체크박스·하단 작업바, 해제 시 원상복귀 |
| 실제 파일 삭제·이름 변경 | 위험도·대상·영향·백업 확인을 표시하는 별도 확인 단계 |
| 대체 원형 퀵 메뉴 | **선택형·실험적**: 최대 4~6개 자주 쓰는 동작만, 텍스트 힌트와 일반 목록 메뉴로 대체 경로 제공 |

### 3-7. 프로토타입에서 실제 확장으로 가져가는 순서

1. 현재 `main`의 실제 이벤트/탐색/저장 API 및 테스트 파악.
2. **정보 구조 이식**(헤더/두 탭/목록/전역·목록·항목 메뉴)만 먼저 적용. 기존 기능은 사라지지 않도록 경로 유지.
3. **채팅 설명** 데이터 계약과 백업 이전 계획 확정 후 별명 UI 교체. 메타데이터를 잘못된 채팅에 재연결하지 않는다.
4. 눈 전용 툴팁 → 비활성 채팅 조회 어댑터 → 전체 목차/마지막 메시지 상세 미리보기 순서로 기능 연결.
5. B-05/06 실제 ST 스크롤·동적 메시지·마지막 답변 테스트 후 이동 규칙 채택.
6. 스와이프 진입은 **메시지 본문 상단 도구 모음**에서만 별도 기능·호환성 테스트 후 개발.
7. 매 단계마다 브라우저/모바일/키보드 테스트 및 버전·문서·백업 영향 확인. **프로토타입의 데모 데이터 조작을 실 데이터 구현으로 간주하지 않는다.**

## 4. 아키텍처와 데이터 설계의 공통 계약

권장 의존성 방향:

1. **SillyTavern Adapter:** 공식 API, 버전별 기능 탐지, 이벤트 구독, 파일 정보 읽기/전환/저장.
2. **Domain & Identity:** 채팅·메시지·스와이프 식별, 메타데이터 의미, 정렬·필터 순수 함수.
3. **Repository:** 사용자 관리 데이터의 읽기/쓰기/백업/마이그레이션, 인덱스 캐시.
4. **Services:** 이동, 검색, 미리보기, 스와이프 비교, 파일 일괄 작업의 유스케이스.
5. **UI:** 탭/패널/목록/도구/로딩/알림, 이벤트를 서비스에 전달.
6. **Themes:** UI 공통 CSS 토큰 위의 프리셋. 내부 ID나 실제 파일명 참조 금지.

새 파일/모듈은 필요한 시점에만 분리한다. '미래를 대비한다'는 이유만으로 실제로 사용하지 않는 추상화와 프레임워크를 대량 도입하지 않는다.

### 식별자 관련 사고 예방

- **채팅**: 같은 파일 이름이 다른 캐릭터나 그룹에 있을 수 있다. 항상 범위를 포함해 확인한다.
- **메시지**: 화면 번호(#0, #1...)는 순서가 바뀌면 달라질 수 있다. 기존 사용자 지정 제목 ID를 맹목적으로 복사하지 않으며 중복·삭제·브랜치 검증이 필요하다.
- **스와이프**: 배열 순서는 안정된 정체성이 아니다. 변경/삭제에 대비한 매핑과 충돌 감지가 필요하다.
- **폴더·태그**: 사용자가 보는 이름은 변경 가능해야 하므로 내부 ID를 별도 관리한다.
- **생성일/활동일**: 원시 데이터의 출처와 확실성(실측/추정/미상)을 함께 저장·표시한다.

### 저장과 안전

- 데이터는 schemaVersion을 갖고, 손상된 값은 검증 실패 처리. 잘못된 저장소 상태에서 조용히 덮어쓰지 않는다.
- 가능하면 덮어쓰기 전에 변경 미리보기/백업을 제공하고, 중복 저장·채팅 전환 중 레이스를 막는다.
- 외부 확장이 같은 메시지/DOM을 갱신하더라도, 확장의 데이터 키와 CSS 선택자가 다른 확장 영역을 덮지 않게 한다.
- 화면이 보이지 않거나 데이터가 누락되었을 때 정상 채팅 자체를 차단하지 말고 확장 기능만 안전하게 실패하도록 한다.

1. 사용자 요청·기대 동작·비범위를 명확히 기술.
2. 관련 기존 코드와 본 문서·현재 브랜치를 읽고 의존성 확인.

4. 단위 테스트 및 필요 시 DOM/브라우저 통합·실사용 확인 항목 추가.

6. 기존 데이터 호환·마이그레이션·백업 경로를 점검.
7. README/변경 로그/이 지침서의 상태를 실제 코드와 동기화.
8. 원본 버전 보존(브랜치/PR), 위험한 병합·삭제는 승인과 검증 후 진행.

## 7. 보류 중 결정 사항 (정책을 임의 확정하지 말 것)

- 채팅 관리 대상: 현재 캐릭터/그룹만 우선할지, 모든 캐릭터를 포함한 전역 라이브러리를 언제 지원할지.
- 폴더: 채팅당 한 폴더 + 다중 태그를 기본값으로 할지, 복수 폴더 소속·중첩을 지원할지.
- 채팅 고유 ID: 읽기 전용 외부 매핑 vs 채팅별 메타데이터 삽입, rename/clone/Cut & Paste 동작 정책.
- 생성일 정보: 신뢰 가능한 원본 필드와 추정값의 처리/정렬.
- 커스텀 표지: 저장 위치, 이동/백업/복원 경로, 최대 용량.
- 검색 인덱스: 파일/로컬 저장소/메모리 사용 범위, 갱신 규칙, 개인정보 처리.
- 스와이프 ID: 개별 답변 변경/복사/삭제에 대한 안정 식별 정책.
- 개요 열기 동작: 항상 최신으로 시작 vs 직전 탐색 위치 유지.
- 마지막 메시지 버튼의 2단계 상태가 설정 변경/테마 변경 시 어떻게 동작할지.
- 데스크톱/모바일의 기본 UI 규칙과 확장 배포 대상 SillyTavern 버전 범위.
- **채팅 설명 전환:** `stmn_library_v1.records[*].alias`를 설명으로 이관할지, 독립 필드를 도입할지. 기존 JSON 백업과 가시적 원본 파일명 우선 정책 보존.
- **미리보기 조회:** 비활성 채팅의 전체 메시지 목차·본문을 실제 채팅 전환 없이 안전하게 읽는 공식/검증된 경로, 대량 데이터 지연 로드와 취소.
- **UI 프로토타입 이식:** 기본 미니멀 레이아웃과 클래식/금지된 층/스카이 리프트 테마 공존 방식, 모바일/터치 미리보기 동작, 폴더 사이드바 기본 열림/닫힘.
- **스와이프 메뉴 위치:** 메시지 원래 상단 도구 모음에 버튼을 추가하는 방식의 API·호환성, 데이터 쓰기·활성화 책임과 실측 테스트.
- **새 스크롤 이동 규칙:** B-05/06에서 '현재 메시지 시작 위치' 판단 허용 오차, 콘텐츠 높이 변경과 자동 스크롤 충돌.
- **디자인 및 제품 이름은 미확정:** 현재 엘리베이터는 가변 프리셋 중 하나가 될 수도 있다.

A~D 실제 구현 상태와 **독립 Quiet Elevator v5 HTML 실험**을 분리. 초보자 중심 10개 목적별 카테고리/3종 메뉴(전체·목록·항목), 최소 노출·여백 중심 화면, 채팅 설명과 원본 파일명 표시 정책, 눈 아이콘 아래 전용 툴팁(채팅 최신 제목 5개 + 본문 최대 680자), 상세 전체 목차, 펼치는 폴더 탐색, 별 옆 연필 버튼, B-05/06 이전·다음 2단계 요구, 스와이프 메시지 상단 도구 진입 위치를 기록. 개발 완료라고 주장하지 않음.
