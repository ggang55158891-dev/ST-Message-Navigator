# ADR-001 — 채팅 관리 데이터의 참조·저장·백업 방식

**상태:** C단계 첫 구현 채택 · **작성일:** 2026-11-02

## 1. 불변 원칙

- 실제 채팅 JSONL, 메시지 본문·제목, 다른 확장 설정을 이 관리 시스템 때문에 다시 쓰지 않는다.
- 현재의 엘리베이터 UI/건물 개념과 관리 데이터 모델을 분리한다.
- 데이터가 손상되거나 새 스키마라서 해석할 수 없으면 조용히 초기화하지 않는다.
- 초기화, 메시지 이동, 채팅 변경 이벤트에서 관리 데이터 저장소 전체를 읽거나 새로 저장하지 않는다.

## 2. 채팅 참조

참조 키는 JSON 배열 [범위 식별자, 원본 채팅 파일 ID]를 직렬화한 문자열이다.

- 범위: character:(캐릭터 avatar 파일명) 또는 group:(그룹 ID). 현재 건물 로비 컨텍스트와 같은 기준.
- 채팅 파일 ID: JSONL 접미사를 제외한 원본 파일 식별자. 별명이나 표시 이름은 식별자가 아니다.
- 장점: 서로 다른 캐릭터·그룹의 **동일 파일명**은 서로 다른 관리 정보를 가질 수 있다.
- 한계: 이 참조는 영원히 변하지 않는 UUID가 아니다. 파일명 변경, 아바타 이름 변경, 복제·이동은 원래 참조를 끊을 수 있다. 다른 파일에 잘못 붙이는 것보다 기존 정보를 **고아로 보존**하는 정책을 택한다.
- 원본 채팅에 ID를 새로 삽입하지 않는다. 추후 식별자 이전·재연결 UI와 Cut & Paste 호환을 별도 설계.
- 기존 메시지 제목의 stmn_message_outline_v1 및 stmn_message_id_v1과 무관하다.

## 3. 저장 위치 및 구조

**채택:** SillyTavern 확장 설정 객체의 독립 네임스페이스 stmn_library_v1. v1 저장소 형태는 schemaVersion, records, folders, tags.

- records: 참조 키별 alias, folderId, favorite, tagIds, imageRef, lastRead, customSortOrder, createdAt, createdAtSource.
- folders/tags: 내부 ID와 표시 이름을 분리. 중첩 폴더/다중 폴더 정책은 아직 확정하지 않는다.
- 설정 백업과 관리 데이터 백업은 분리. 나중에 채팅 이미지와 전문 검색 인덱스를 관리 설정에 넣지 않는다.
- 초기 실행/패널 열기에서 빈 저장소 자동 생성 없음. 수동 백업·상태 검사·복원 때만 검증.
- 디스크 저장 요청은 SillyTavern의 saveSettingsDebounced 메서드를 사용하며, 요청 시 비동기 내구성이 확정되는 것은 아니다.
- 데이터는 최대 256KB(간결한 JSON), 관리 채팅 2000개, 폴더 200개, 태그 300개. 이 제한을 넘으면 저장 거부. 더 많은 채팅을 관리하려면 별도 서버 확장 데이터 파일이나 검증된 API로 이전할 계획.

**대안과 판단:**
- JSONL/chatMetadata: 채팅별로 저장되지만 비활성 채팅 전역 관리 및 복제 시 연결 문제·원문 수정 위험.
- localStorage/IndexedDB: 로컬에서 빠르지만 브라우저나 기기가 달라지면 이전이 어렵고 클라이언트 초기화 시 소실 가능.
- 확장 전용 서버 파일: 대규모 관리에 더 적합하지만 API/버전/권한 검증이 필요하므로 다음 저장소 단계에서 검토.
- extensionSettings: 이미 사용 중인 ST API이므로 C단계에서는 작은 메타데이터에 한정해 선택.

## 4. 백업과 충돌 정책

- 별도 타입 stmn-chat-library, 관리 스키마 v1, 백업 생성 시각과 확장 버전을 기록한다.
- **채팅 원문·메시지 제목은 포함하지 않는다.** 다만 파일명 참조, 사용자가 붙인 별명, 폴더·태그 이름은 백업에 기록되어 있으므로 파일 공유 전에 직접 확인한다.
- 가져오기: 파일 크기 → 지원 스키마 → 필드/식별자 → 연결 관계 → 저장 크기를 검사.
- 관리 데이터 병합 복원은 없는 항목만 추가하고, 기존 ID의 값이 다르면 **전체 병합을 거부**한다. 부분 적용이나 무단 덮어쓰기는 금지.
- 파일 선택 → 차이 미리보기 → 명시적 동의 → 저장 직전 재검증 → 저장 요청.
- 즉시 예외 발생 시 이전 데이터 객체를 복원하며, 저장 요청 후 실제 디스크 기록 완료까지 보증하지는 않는다.
- 기존 A-03 설정 JSON 백업(7~8 항목)은 그대로 지원. 관리 데이터 백업과 서로 혼용하지 않는다.
- 삭제된 채팅의 관리 정보는 자동 삭제하지 않는다(오인 삭제보다 보존). 나중에 고아 감지·재연결 UX 구현.

## 5. D단계 전 남은 결정

- 폴더 소속 개수와 중첩 여부, 태그 수정/삭제 UX 및 별명 관리 화면
- 이미지 파일의 보관 위치와 용량 제한
- 생성 날짜 출처와 정확도 표시
- 캐릭터 아바타 변경·파일명 변경·복제 후 명시적 재연결
- 관리 데이터 규모가 커질 경우 안전한 이전/멀티기기 충돌 보호
- 실제 SillyTavern 및 Cut & Paste 확장과의 통합 테스트

## 6. 검증

동명 파일 분리, 범위 식별, 잘못된 백업 거부, 프로토타입 오염 방지, 원본 불변, 다른 확장 설정 불변, 사용자 동의 전 저장 0회, 충돌 시 0회, 정상 병합 1회, 저장 함수 즉시 실패 시 롤백을 Node·Chromium 모의 ST 테스트에서 검사한다. 실제 ST 재시작 후 설정이 지속되는지 수동 확인은 별도다.
