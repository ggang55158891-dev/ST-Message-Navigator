# Quiet Elevator · 단계별 UI 이식 계획

> 기록일: 2026-11-03 · 기준: main v1.6.0 + 독립 실험용 \`Quiet_Elevator_v5_툴팁_목차_설명수정.html\`
>
> **이 문서는 개발의 방향이지 최종 UI 고정안이 아니다.** 사용자가 버튼 위치·메뉴 구성·테마를 추후 자유롭게 조정할 수 있다. 실제 SillyTavern 연동·검증 상태와 독립 HTML 시뮬레이션 기능을 혼동하지 않는다.
>
> 전체 원칙·로드맵·데이터 안전 기준: [DEVELOPMENT_GUIDE.md](DEVELOPMENT_GUIDE.md).

## 방향

- 채팅과 메시지의 **이동/관리**가 핵심이다. 여백 중심의 극단적 단순 UI를 적용하되, 숨긴 기능을 사라지게 만들지 않는다.
- 기능을 목적별 **이동·검색·미리보기·분류·편집·스와이프·파일·일괄작업·화면·데이터**로 정리한다.
- 사용자의 기대와 조작: **행 클릭=이동, 눈=미리보기, 별=즐겨찾기, 연필=즉시 편집, ···=해당 항목 관리**.
- 메뉴는 **전체 / 목록 / 항목별**의 세 진입점으로 제한하고, 장기적으로 깊이 2단계 이하로 유지한다.
- 실제 원본 파일명 변경·삭제·복제 등의 파괴적 기능은 **가상 분류**와 별도로 보존·확인한다.
- HTML 시안의 외형/버튼 위치는 **참고 자료**이며 새 기능이 추가될 때 사용성 기준으로 조정 가능하다.

위 Q단계는 장기 가이드의 B~H 단계를 **대체하지 않고 UI 통합 순서를 명확히 보조**한다.

## Q-01 구현 세부 범위

- 기존 \`elevatorTheme\` 설정에 \`quiet\` 선택지만 추가한다. **기본값은 이전과 동일한 \`classic\`**. 설정 백업 필드 개수/스키마는 그대로이며 이전 백업 복원도 유지.
- \`quiet-ui.js\`는 기존 DOM·액션에 **얇은 사용자 인터페이스만 추가**한다. 탐색 엔진·저장소·채팅 파일·외부 의존성을 수정하지 않는다.
- **상단 전체 메뉴:** 기존 SillyTavern 엘리베이터 확장 설정으로 이동하는 진입점(화면·조작 / 백업·복원 / 진단). 확장 설정이 앱 외부에 접혀 있다면 이를 열어야 할 수 있다.
- **상단 검색:** 평소 닫혀 있고 버튼을 누르면 해당 탭 검색 입력이 표시됨. 닫으면 사용자가 보지 못하는 필터가 남지 않도록 쿼리를 초기화.
- **층 안내 목록 메뉴:** 모두 펼치기·모두 접기. 기존 10개 그룹과 개요 이동 버튼, 제목 편집 동작 그대로 유지.
- **건물 로비 목록 메뉴:** 실제 기존 정렬/전체·폴더별·즐겨찾기 필터, 분류 관리 UI, 새로고침 기능으로 연결.
- **별명/원본 파일명 표시:** v1.6.0 기능 그대로 유지하며 이번 단계에서는 설명 데이터로 강제 변경하지 않는다.
- **모든 기능 유지:** 기존 UI 템플릿도 유지하므로 테마 선택을 바꿔 이전 레이아웃으로 돌아갈 수 있어야 한다.

## 남겨둘 문제

- 실제 \`Quiet_Elevator_v5_툴팁_목차_설명수정.html\`은 **독립 실험판**이며, 이 PR은 실험 데이터를 실제 채팅으로 옮기지 않는다.
- Quiet Q-01의 화이트 미니멀 외관은 사용자가 추가로 바꿀 수 있으며, 테마가 맘에 들지 않으면 기존 프리셋으로 전환한다.
- **Q-02 설명 마이그레이션:** \`stmn_library_v1\`의 \`alias\`는 사용자 데이터. 이름 필드의 의미를 조용히 재정의하지 않는다.
- **Q-04 다른 채팅 미리보기:** 현재 채팅을 바꾸지 않고 비활성 채팅 JSONL을 조회할 수 있는 경로를 실제 ST 환경에서 먼저 확인한다.
- **Q-06 스와이프:** 독립 HTML 스와이프 버튼이 실제 SillyTavern의 활성 스와이프 변경 구현을 증명하지 않는다.


## Q-02 실제 구현 세부 (v1.8.0 PR)

- 10개 카테고리 중 메시지/채팅 **항목별 접근 경로**를 먼저 단순화. Quiet에서 별·연필·정보 눈·`···` 사용.
- 채팅 목록의 **파일명은 원본**, 사용자 **채팅 설명은 별도 필드 `description`**. 오래된 `alias`는 절대 설명으로 몰래 바꾸지 않음.
- 관리 데이터 `stmn_library_v1` 저장 키는 유지하되 **schemaVersion=2**로 갱신. 기존 v1 레코드·백업은 검증 후 메모리 변환하고, **유효한 변경 작업이 생겨야** v2로 저장. 신규 v2 백업에 설명 포함. 과거 릴리스로 되돌리려면 이전 백업이 필요할 수 있음.
- 메시지 북마크는 `chatMetadata[stmn_message_outline_v1].bookmarks`에 stable message ID별로 저장. 자동 제목·커스텀 제목·본문·스와이프와 분리, 실제 ST 메타데이터 저장 기능을 사용.
- 채팅의 눈 버튼은 **현재 로비에서 이미 가지고 있는 파일명·설명·폴더·태그·메시지 수**만 표시함. 메시지의 눈 버튼은 **현재 로드된 메시지의 처음 680자**를 클릭 시 보여줌.
- **Q-04의 눈 hover 툴팁 / 비활성 채팅 본문·전체 목차는 아직 구현하지 않음.** 스와이프 전체 보기/변경도 Q-06.
- Quiet에서 `···`은 파일 관리 기능의 **예정 구역**을 텍스트로 구분하되 실제 삭제 등 위험한 기능 버튼은 제공하지 않음. 다른 세 테마의 기존 별명과 분류 UI는 유지.


## Q-02 수정 및 Q-04 일부 선행 (v1.9.0 PR)

- Q-02의 **눈 클릭 = 처음 680자**는 v5의 의도와 달라 **오류로 수정**함. 길이 제한은 **눈 전용 hover/focus 툴팁(680자)** 에만 해당. **눈 클릭 = 해당 메시지 원문 전체 + 모든 스와이프의 완전한 원문 탐색**, 상세 영역 내부 독립 스크롤.
- 스와이프 선택 적용은 ST의 공개 `getContext().swipe.to` API를 경유, 직접 JSONL/DOM을 수정하지 않음. 메시지 렌더링이 필요한 경우 기존 navigate로 보장 후 처리.
- 업데이트 버튼은 설정 첫 줄에 표시, ST 서버의 설치 Git 브랜치 status에 따라 강조되고 명시적 클릭 시 업데이트. 서버 권한/브랜치 정책 유지, 완료 뒤 새로고침.
- Q-03 폴더 트리, 다른 채팅 메시지 목차/마지막 메시지 조회 및 스와이프 즐겨찾기 등은 여전히 별도 개발 예정. Quiet v5 시안의 세부 UI는 향후 변경 가능.


## Q-03 실제 구현 (v1.10.0 PR)

- Quiet 건물 로비에서 폴더 아이콘으로 **독립 탐색 드로어** 열기·닫기. 전체/즐겨찾기/각 폴더/미분류는 각각 독립적으로 접고 펼칠 수 있으며, 아래에서 채팅 제목을 선택해 원래의 채팅 전환 로직으로 이동.
- **섹션 펼침과 목록 필터를 분리**: 펼침은 포함된 채팅을 확인하는 동작, **이 목록만 보기**는 오른쪽 목록에 필터를 적용하는 동작. 이전 '폴더별 보기' 메뉴가 관리 편집기를 여는 동작은 변경.
- 대량 채팅 최적화: 폴더가 닫혀 있으면 항목 DOM 생성하지 않음. 펼친 폴더만 최대 **30개씩 더 보기**, 일반 목록은 기존 100개씩 로드. 다른 채팅 파일을 개별로 열거나 내용 검색을 실행하지 않음.
- 현재 캐릭터/그룹 소유 범위의 채팅만 표시. 실제 파일 이동·삭제 없음, 설정 스키마/별명/태그/북마크 불변.
- 좁은 패널에서는 드로어를 겹쳐 표시. 외형 세부 배치는 향후 사용자 테스트를 통해 변경 가능.


## Q-04 실제 구현 (v1.11.0 PR)

- 별·설명 연필 옆의 채팅 **눈 버튼**을 미리보기로 연결. hover/focus에서만 최근 **5개 메시지 제목**과 마지막 메시지 본문 **최대 680자**, 클릭하면 **전체 메시지 목차**(사용자 지정 제목 포함)를 보여줌. 툴팁은 눈 아이콘 아래에 놓고 다른 채팅으로 전환하지 않음.
- 목차는 서버에서 일시적으로 전체 JSONL을 받아 계산하지만 **제목/번호와 마지막 발췌만 남김**. 대용량 채팅은 **가상 스크롤**로 제한된 DOM, **260ms 호버 지연**, 한 번에 한 요청, **3개·90초짜리 소형 LRU 캐시**. 초대형 JSONL의 서버 응답 전송량 자체를 줄이는 API는 추후 ST 서버 측 지원이 필요.
- 캐릭터/그룹에 따른 공식 읽기 전용 요청만 사용. 현재 소유 범위에 있는 파일 ID인지 확인하고, 상세 목차에서 제목을 클릭했을 때만 **명시적으로 채팅 전환 + 해당 메시지 이동**.
- 테마/탭/캐릭터·그룹 범위가 변경되면 툴팁·상세 패널·미리보기 캐시를 정리. 오류/취소/키보드·터치 접근 대응.
- 기존 저장 스키마(관리 v2, 메시지 제목·별명·설명·폴더·북마크) 및 원본 채팅 JSONL **수정 없음**. Q-05 이동 규칙 및 Q-06 추가 스와이프 분류는 아직 남음.


## Q-05 실제 구현 (v1.12.0 PR)

- 이전 버튼의 **현재 메시지 중간 → 현재 메시지 시작 → 이전 메시지** 2단계 규칙. 화면 좌표로 읽기 위치를 확인하되 기존 명시적 NavigationCursor를 유지하여 마지막 근처 스크롤 클램핑 때문에 #7→#5처럼 건너뛰지 않음. 수동 스크롤/채팅 전환 시 상태 초기화.
- 마지막 메시지에서 **다음 버튼**도 실제 화면 최하단까지 이동. 기존 마지막 버튼의 1회 시작·2회 맨 아래 규칙과 동일한 하단 계산을 재사용. 첫 메시지에서도 중간에서 이전을 한 번 누르면 시작점으로 돌아갈 수 있게 버튼 활성 상태 반영.
- 사용자가 제거 요청한 **탐색 대상 메시지의 흰 테두리**는 확장의 `highlightTarget` 실행 및 CSS 규칙 자체를 삭제. 다른 확장의 아웃라인을 강제 초기화하는 광범위 선택자는 사용하지 않음.
- 실제 채팅 파일/제목/스와이프/설정 저장형식 변경 없음. 리그레션 검사는 Scroll DOM 기하 및 가상 브라우저에서 수행, 다른 최적화 확장과의 실제 통합 검증은 별도 필요.


## Q-06 실제 구현 (v1.13.0 PR)

## Q-07B 실제 구현 (v1.15.0 PR)

- Quiet 채팅 관리 메뉴에서 **파일 이름 변경 · 백업 후**, **파일 삭제 · 백업 후**. 활성 채팅은 제외하고 한 번에 한 비활성 채팅만 수정. 기존 다중 선택은 ZIP 백업 전용으로 유지.
- **원본 JSONL 자동 ZIP 다운로드 요청** → 다운로드 실제 저장/내용을 사용자에게 재확인하는 체크박스 → **기존 파일명 정확히 입력** → 명시적 최종 제출 전까지 삭제/이름 변경 API 호출 없음. 실제 자동 다운로드 완료 여부를 확증할 수 없다는 점을 UI에 명시.
- 캐릭터 파일은 공식 이름 변경/삭제 엔드포인트를 이용하고 현재 채팅 참조를 변경하지 않음. 그룹은 전역 채팅 파일 디렉터리 소유권과 다른 그룹의 중복 참조를 검사한 뒤 그룹 메타데이터 /api/groups/edit도 함께 갱신. 그룹 이름 변경의 두 번째 저장이 실패하면 파일명을 되돌리려고 시도; 그룹 삭제는 그룹 목록 변경을 먼저 커밋하고 삭제에 실패하면 목록 복구를 시도.
- **완전한 트랜잭션/자동 복구 불가능**: 그룹 메타데이터와 JSONL은 별도 요청/저장 리소스이며 네트워크 단절·동시 변경의 모호한 성공을 되돌리기 어렵다. 이 경우 성공이라고 표시하지 않고 수동 점검을 안내.
- 채팅별 파일명에 연결된 확장 라이브러리 레코드는 검증된 복사본에서만 새 ID로 이동 또는 삭제(폴더·태그·즐겨찾기·설명 보존). 관련 메타데이터 저장 실패 시 경고를 제공하고 원래 관리 레코드를 강제 삭제하지 않음. 원본 JSONL ZIP에는 별도 라이브러리 설정이 들어가지 않으므로 별도 라이브러리 백업 필요.
- Node: 캐릭터/그룹 엔드포인트, 활성 채팅 거부, 중복/경로 차단, 그룹 메타데이터 실패 시 이름 역변경, 삭제 오류 시 목록 복구, 설정 참조 이동/삭제. Chromium: 백업 선행·입력 확인 전 작업 API 미호출, 실제 비활성 파일 변경, 서버 오류에서도 현재 채팅 불변 확인.
