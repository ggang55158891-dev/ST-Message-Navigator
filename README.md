# Message Navigator & Outline for SillyTavern

> **장기 개발 참고 문서:** [개발 지침서·단계별 로드맵](docs/DEVELOPMENT_GUIDE.md) · [개발 도우미 안내](AGENTS.md)

SillyTavern용 채팅·메시지 네비게이션 확장 (현재 manifest 버전: v1.3.1)

## 설치 (Windows 11 포함)

1. `st-message-navigator.zip`을 압축 해제합니다.
2. 압축 내의 **`st-message-navigator` 폴더 전체**를 SillyTavern 설치 폴더의 다음 위치에 복사합니다.
   `SillyTavern/public/scripts/extensions/third-party/st-message-navigator/`
   - `manifest.json` 파일이 위 폴더 바로 아래에 있어야 합니다.
3. SillyTavern을 새로고침합니다. **오른쪽(기본값)에 다섯 개의 원형 버튼**이 나타납니다.
4. 확장 설정(Extensions 패널)의 `Message Navigator & Outline (메시지 탐색)` 항목에서 이동 범위와 버튼 위치를 선택합니다.

설치가 안 되면 `F12 → Console`에서 `[ST Message Navigator]` 메시지를 확인하세요.

## 버튼 (위에서 아래)

1. 첫 메시지로 이동
2. 이전 메시지로 이동
3. 채팅 개요(목차) 열기/닫기
4. 다음 메시지로 이동
5. 마지막 메시지로 이동

* **모든 메시지:** `is_system === true`로 숨김 처리된 메시지도 이동 대상에 포함합니다.
* **숨김 메시지 제외:** 앞/뒤 네비게이션에서 숨김 메시지를 건너뜁니다. 개요 패널에서는 숨김 메시지도 흐리게 표시하며 직접 클릭해서 이동할 수 있습니다.
* 목차에서 제목을 클릭하면 해당 메시지로 이동합니다. 제목 옆 연필 버튼으로 **제목만** 수정합니다. 원문 메시지 내용은 변경되지 않습니다.
* 제목을 공백으로 저장하면 자동 제목으로 돌아갑니다.
* 목차 검색창에서는 제목·본문 앞부분·발화자 이름을 검색할 수 있습니다.

## 저장 및 브랜치

* 제목은 **채팅별 메타데이터**(`chatMetadata.stmn_message_outline_v1.titles`)에 저장됩니다.
* 제목을 수정한 메시지에만 `stmn_message_id_v1`라는 고유 식별자 필드가 생깁니다. `mes` 본문과 `extra` 필드는 변경하지 않습니다.
* 일반적인 SillyTavern 브랜치/체크포인트는 메시지와 채팅 메타데이터를 복사하므로, **브랜치를 만든 시점까지 존재하던 제목**이 함께 복제됩니다. 이후 원본 채팅과 브랜치는 각각 독립적으로 수정할 수 있습니다.
* **이미 존재하는 브랜치로 변경 사항을 실시간 동기화하지는 않습니다.**
* 실리태번 내장 저장 API를 사용합니다. 채팅 파일(.jsonl)을 다른 프로그램에서 편집한다면 백업을 먼저 준비하세요.

## 호환성과 한계

* SillyTavern **release 최신 소스**의 `getContext()`, `showMoreMessages()` 및 DOM 구조를 바탕으로 작성되었습니다.
* 다른 확장의 CSS/DOM이나 실리태번 내부 전역 변수를 수정하지 않습니다. UI 이벤트와 확장 전용 데이터 키를 사용합니다.
* 과거 메시지가 화면에 없으면 ST의 자체 렌더러로 180개씩 추가 로딩합니다. 채팅이 매우 길면 첫 메시지로 이동할 때 다소 느려질 수 있습니다.
* SillyTavern이 자체 DOM 구조나 내부 `showMoreMessages` export를 변경하는 경우 호환성 수정이 필요할 수 있습니다(버튼 클릭 경로로 보조 폴백 제공).
* 앱이 직접 다른 메시지 객체를 복제하면서 기존 확장 식별자까지 복사한 경우, 해당 복제본 제목을 새로 저장할 때 식별자를 분리합니다.
* `is_system`은 ST의 숨김 플래그이며, CSS `display:none`으로 강제로 숨긴 메시지는 스크롤할 수 없습니다.
* 다량의 영상/이미지, Stream 중 DOM 변경, 스와이프 플러그인 동시 구동 등 환경 차이에 따라 실제 동작 검증이 필요합니다.
* 이 배포본은 **코드 문법 검사 및 모의 데이터 단위 테스트**를 통과했지만, 사용자의 SillyTavern 설치 환경에 접속해 통합 테스트한 것은 아닙니다.

## 개발 및 테스트

`node --experimental-default-type=module --test tests/*.test.mjs`

코드 구성: `index.js`(초기화), `model.js`(탐색/제목/저장), `scroll.js`(ST 메시지 로딩), `ui.js`(버튼/개요/설정), `style.css`(전용 스타일).

## v1.0.1: 메시지 이동 위치 수정

* 이전/다음 버튼은 **마지막으로 명시적으로 이동한 메시지**를 기준으로 이동합니다. 채팅 끝에서 스크롤이 제한되어 앞 메시지가 화면 맨 위에 보이더라도 건너뛰지 않습니다.
* 사용자가 직접 스크롤하면 해당 위치를 다시 계산합니다. 다른 채팅으로 전환해도 이전 위치 정보가 남지 않습니다.
* 목차에서 선택한 메시지를 잠시 테두리로 표시하여 긴 메시지 및 채팅 하단에서도 이동 대상을 명확하게 알 수 있습니다.
* 테마에서 부드러운 스크롤이 설정되어 있어도 이동 명령은 즉시 완료하도록 수정했습니다.

## v1.1.0: 버튼 드래그 및 개요 가독성

* 데스크톱 버튼은 42px에서 38px, 모바일은 36px에서 34px로 조금 작아졌습니다.
* 다섯 버튼 가운데 아무 버튼이나 잡고 드래그하면 전체 묶음을 이동할 수 있습니다. 위치는 화면 크기에 상대적인 좌표로 저장되어 새로고침 후에도 유지됩니다.
* 확장 설정에서 좌/우 배치를 다시 선택하면 드래그 위치를 초기화합니다.
* 목차의 제목은 16px, 발화자 정보는 9px로 조정했습니다.
* 기존 메시지 이동 로직은 그대로 유지합니다.

## v1.2.0: 번호 통일, 표시 스위치, 접기/펼치기 및 정확한 번호 검색

* **SillyTavern 번호와 일치**: 개요 패널의 첫 메시지는 `#0`, 두 번째는 `#1`로 표시합니다. 번호와 제목 수정 도구의 안내 문구, 이동 상태 메시지도 0부터 시작합니다.
* **메시지 이동 버튼 표시 스위치**: 확장 설정의 '메시지 이동 버튼 표시'를 끄면 가운데 '메시지 개요 열기/닫기' 버튼만 남습니다. 다시 켜면 5개 버튼이 복원됩니다. 설정은 유지되며 드래그 위치를 계속 사용할 수 있습니다.
* **확장 이름 및 기본 제목 HTML**: 확장의 표시 이름과 설정 제목을 '메세지 네비게이터'로 바꾸고 설정 제목의 별도 테두리와 굵기 스타일을 제거해 기본 `<details><summary>` 표시 방식을 사용합니다.
* **10개씩 접기/펼치기**: `#0–#9`, `#10–#19` ... 그룹을 개별적으로 접거나 펼칠 수 있고 '모두 펼치기'/'모두 접기'가 있습니다. 큰 채팅의 가상 스크롤 처리도 유지됩니다. 채팅을 바꾸면 그룹 접힘 상태는 초기화됩니다.
* **메시지 번호 정확히 검색**: 검색창에 `#4`라고 쓰면 메시지 ID 4만 보여줍니다. 일반 단어 검색은 종전처럼 제목, 메시지 내용, 캐릭터 이름을 검색합니다. 검색 결과는 접힌 그룹에서도 표시됩니다.
* 메시지 이동, 제목 저장 및 드래그 기능의 핵심 동작은 변경하지 않았습니다.

## v1.3.0 · 엘리베이터: 건물과 층

SillyTavern의 **채팅 파일 하나를 건물 하나**, 각 채팅의 **메시지 번호를 층**으로 표시합니다.

- 기존 5개 탐색 버튼과 메시지 개요, 번호 검색, 그룹 접기/펼치기, 제목 수정, 버튼 드래그는 유지됩니다.
- 패널 상단 디지털 표시판에 **현재 건물(채팅 이름)**과 **현재 층(#메시지 번호)**을 표시합니다.
- **층 안내 / 건물 로비** 탭을 전환할 수 있습니다.
- 건물 로비는 **현재 선택한 캐릭터 또는 그룹에 속한 채팅**을 나열합니다. 채팅 검색, 이름순/최근 활동순 정렬, 새로고침을 지원합니다.
- 건물을 클릭하면 SillyTavern 공식 `openCharacterChat()` 또는 `openGroupChat()`을 호출합니다. 원본 파일을 직접 수정하지 않습니다.
- 현재 캐릭터/그룹에 속하지 않은 다른 캐릭터의 채팅까지 한 번에 찾아가는 전역 라이브러리는 **아직 지원하지 않습니다.**
- 현재 선택한 채팅에서 다른 채팅으로 이동하면 편집 중이던 입력이나 생성 중 상태 등 SillyTavern의 기존 전환 정책이 적용됩니다. 중요한 미완성 작성 내용은 직접 저장한 뒤 전환하세요.

### 엘리베이터 외형

확장 설정에서 프리셋 선택:
1. **클래식:** 무광 금속과 밝은 LED 표시판.
2. **금지된 층:** 낡은 금속과 붉은 조명.
3. **스카이 리프트:** 반투명 하늘색 유리. 낮은 구름, 밤은 별빛. 밝기 설정 **자동/낮/밤** 지원. 자동은 브라우저/운영체제의 `prefers-color-scheme`을 따릅니다.

스타일은 `#stmn-root` 아래에 한정하여 SillyTavern 본체나 다른 확장의 테마를 변경하지 않습니다.

### 개발 및 테스트

`node --experimental-default-type=module --test tests/*.test.mjs`

새 파일: `building-data.js`(표시 데이터 처리), `buildings.js`(SillyTavern 채팅 목록·전환 어댑터), `elevator-ui.js`(탭·건물 패널·테마).

> 이 버전은 실제 SillyTavern 브라우저와 설치된 다른 확장들을 조합한 통합 테스트가 별도로 필요합니다. 먼저 새 브랜치를 시험 설치하고, 정상 동작 확인 후 병합하세요.


## v1.3.1: 안전한 오류 진단 (로드맵 A-01)

확장 설정 → **오류 진단 및 내보내기**를 열면 다음 작업을 할 수 있습니다.

- **자세한 진단 기록 켜기/끄기**: 기본값 꺼짐. 꺼져 있어도 오류의 유형/코드만 임시 메모리에 보존합니다.
- **기록 미리보기**: 가장 최근 20개 이벤트를 확인합니다.
- **JSON 다운로드**: 저장된 최대 120개 이벤트를 사용자 조작 시에만 다운로드합니다.
- **기록 지우기**: 메모리에 남은 이벤트를 삭제합니다.

### 개인정보 설계

- 원문 메시지, 채팅 파일명, 캐릭터명, URL, 파일 경로, 오류 문구, 스택 트레이스, 프롬프트는 기록하지 않습니다.
- 이벤트 분류·코드·상태·메시지 **숫자 인덱스**·개수·경과 시간·기본 오류 유형만 허용 목록에 따라 기록합니다. 채팅 ID는 기록하지 않습니다.
- 로그는 브라우저 메모리의 **최대 120개 순환 버퍼**에만 남으며, 새로고침하면 사라집니다. 외부 서버로 전송하지 않습니다.
- 디버그 결과를 남에게 보낼 때는 다운로드 파일을 직접 읽어보고 공유하세요.

### 직접 확인할 항목

1. 설치 후 확장 설정에 진단 메뉴가 나타나는지 확인.
2. 진단 모드를 켠 다음 다른 메시지/채팅으로 이동 → 미리보기에서 navigation 또는 chat-switch 이벤트가 나타나는지 확인.
3. 끈 후에는 정상 이벤트가 쌓이지 않는지 확인.
4. JSON 다운로드 → 파일에 메시지 본문·파일명·캐릭터명·오류 문구가 없는지 확인.
5. 기존 메시지 이동, 개요, 채팅 전환 기능이 평소대로 동작하는지 확인.

**검증 범위:** 이 변경에서는 진단 데이터 구조의 단위 테스트와 CI 문법 검사를 추가합니다. 실제 SillyTavern 브라우저 통합 테스트(A-02)와 확장 설정 백업·마이그레이션(A-03)은 후속 별도 업데이트이며, 이 PR에서 완료된 것으로 취급하지 않습니다.
